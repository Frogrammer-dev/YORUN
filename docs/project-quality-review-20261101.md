# 프로젝트 품질 검사와 콘텐츠 확장 검토

검토일: 2026-11-01. 현재 로컬 작업 트리 기준. 기존 미커밋 변경을 포함하며 앱 코드를 수정하거나 배포하지 않았다.

## 후속 보안 패치 (2026-11-01)

아래 초기 검사 이후 사용자 요청으로 의존성을 수정했다. Next.js와 eslint-config-next 16.4.0→16.4.3, Zod 4.6.5→4.6.7, jsdom의 간접 의존성 Undici 8.11.2→8.12.3. package.json과 package-lock.json에 반영했고 기존 모바일 명령 등 사용자 변경을 유지했다.

- 프로덕션 빌드 종료 코드 0: 기존 SecurityFatalError 해소.
- 타입 검사 통과, 기본 테스트 339 통과·87 건너뜀, DB 45 통과, lint 오류 0·기존 경고 3.
- 새 빌드를 별도 포트에서 실행한 핵심 러닝 E2E 6개 통과(데스크톱 Chromium, 모바일 Chromium, 모바일 WebKit). 전체 E2E 및 실제 기기 GPS 시험은 아니다.
- 루트 npm audit: critical/high 0, moderate 16. `--omit=dev` 검사 0건.
- 별도 mobile npm audit: moderate 6, critical/high 0. `--omit=dev` 검사 0건. 모바일 의존성은 변경하지 않았다.
- 남은 루트 경고는 ESLint 계열의 minimatch 의존 관계다. 최신 플러그인도 구형 minimatch API를 요구한다. 숫자를 없애기 위한 minimatch 11 강제 override나 audit가 제안하는 ESLint 4/Next lint config 12로의 다운그레이드는 적용하지 않았다.
- 모바일 잔여 경고는 Capacitor CLI의 glob/minimatch 및 xcode/uuid 개발 의존성이다. 별도 도구 업그레이드와 네이티브 빌드 검증이 필요하다.
- 공개 AI API의 사용자 인증·공유 사용량 제한은 의존성 패치로 해결되지 않으며 별도 공개 배포 과제로 남는다. 원격 배포·커밋은 수행하지 않았다.

## 판단

핵심 흐름과 자동 검증을 갖춘 시제품이다. 공개 배포 준비 완료로 판단하기에는 보안 빌드 오류, 실기기 기록 검증, 사람의 그림 인지 검증이 남아 있다. 콘텐츠는 탐색→러닝→작품 보관의 반복 경험을 먼저 강화한다.

## 먼저 해결할 품질 항목

1. **배포 차단: 보안 빌드 오류.** 설치된 Next.js 16.4.0에 대해 빌드와 npm audit 모두 취약점을 보고했다. audit의 Next.js 항목은 GHSA-2464-fhr4-w9xw, GHSA-p3m5-59mp-jv5r, GHSA-673q-mjm6-r5xr이며 수정 가능으로 표시된다. 실제 앱의 악용 가능성까지 재현한 결과는 아니다. 수정 버전을 확인하고 보안 업데이트 후 타입/테스트/빌드/주요 E2E를 다시 통과시켜야 한다. 이번 검토에서 패키지를 변경하지 않았다.
2. **외부 AI 공개 운영의 인증·한도.** `src/app/api/recognition/reference/route.ts`는 Origin 검사와 요청 크기 제한이 있으나 사용자 인증을 요구하지 않는다. `src/lib/art/roadReferenceProvider.ts`의 호출 한도·동시성은 프로세스 메모리다. 키를 설정한 공개 서버에서는 직접 요청으로 공동 한도를 소진할 수 있고 여러 인스턴스에서 전역 비용 한도를 보장하지 못한다. 인증된 사용자별 제한과 공유 저장소 기반 전체 한도가 필요하다.
3. **그림 인지 품질 미보정.** `src/lib/eval/calibration.json`은 calibrated=false, labels=0이다. 77.42는 과거 고정 12조건 오프라인 기하학 점수이며 현재 앱의 사람 인지율이 아니다. 이름을 가린 판정과 이름·참고 그림을 보여준 뒤의 납득도를 별도 측정한다.
4. **실기기 GPS 출시 근거 부족.** 웹·모델 시험과 네이티브 OS 동작은 별개다. Android/iPhone 각각 화면 잠금, 음악 앱 전환, 권한 변경, 종료·복원, 저장 실패를 실제 야외에서 확인해야 한다. 이번 검토는 기기 시험을 수행하지 않았다.
5. **대결은 로컬 시뮬레이션.** `BattleApp.tsx`가 클라이언트에서 승패를 계산하고 전적을 localStorage에 저장한다. 온라인 경쟁 기능으로 확대하려면 서버 판정·기록 검증·중복 보상 방지가 필요하다.

좋은 기반도 있다. GPS 공백을 실제 이동으로 직선 연결하지 않는 기록 모델, 잘못된 좌표·속도 필터, 기록 복원 시험, DB 소유권 및 충돌 검사, 원본 경로와 설명용 그림의 분리가 구현되어 있다.

## 콘텐츠 확장 우선순위 — 구현 제안, 검증된 성과 아님

| 순서 | 콘텐츠 | 기존 기능 활용 | 최소 범위와 확인 지표 |
|---|---|---|---|
| 1 | 그림 도감·완주 배지 | 작품방, 완료 기록 | 검토한 쉬운 모양 3–5개부터 시작. 실제 완료 기록에만 배지, 중복 지급 방지. 첫 코스 완주와 두 번째 러닝 여부 확인 |
| 2 | 주간 그림 미션 | 코스 탐색·저장·작품 | 주 1개 모양, 사용자 거리 선택. 속도 순위 없이 참여·완성 중심. 미션 시작 대비 완료와 다음 주 재참여 확인 |
| 3 | 작품 비교·공유 카드 | 작품 PNG/공유, 목표·실제 경로 | 목표와 달린 선을 비교하되 지도·위치 포함 여부를 선택. 공유 완료와 사용자의 그림 이해도 확인 |
| 4 | 도로에서 발견한 그림 | 기존 발견형·참고 그림 연결 | 소수 지역에서 후보 제안과 보류 경험 검증. 사람이 납득한 비율·보류율·응답시간·실측 비용 확인 |
| 5 | 친구와 비동기 도전 | 대결 시뮬레이션 | 서버 기록 기반 합동 완주나 작품 투표부터 검토. 속도·거리 경쟁과 실시간 PvP는 기록 신뢰성 검증 뒤 진행 |

추천하는 첫 묶음은 **쉬운 그림 3–5개 + 도감 + 첫 완주 배지**다. 이미 있는 탐색·기록·작품방을 연결하고 신규 서버 복잡도를 작게 유지할 수 있다. 도감의 모양 이름과 배지는 사용자 선택/검토된 코스에 근거시키며, 검증하지 않은 AI 분류를 확정 사실로 보상하지 않는다.

## 진행 순서

1. 보안 업데이트와 배포 빌드 복구, 공개 API 인증·비용 제한 정리.
2. 두 플랫폼 야외 기록 시험과 소규모 사람 판정으로 기본 품질 확인.
3. 도감·배지 한 묶음을 시험하고 두 번째 러닝으로 이어지는지 관찰.
4. 검증 결과에 따라 주간 미션·공유를 추가하고 온라인 대결은 뒤로 둔다.

## 범위와 한계

이번에는 전체 브라우저 E2E, 네이티브 재컴파일, 실제 야외 GPS, 외부 AI 호출, UI 시각 검수를 수행하지 않았다. 과거 문서의 검증 결과를 이번 실행 결과로 합산하지 않았다. PPT는 변경하지 않았다.
