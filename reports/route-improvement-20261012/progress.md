# 고정 경로 12조건 개선 — 2026-10-12 (후속 갱신 2026-10-14)

최신 원래12조건 단일 자동 cascade 평균은 **76.8333 → 77.4167점**이다. 도로에서 처음부터 실행하고 독립 full 감사를 통과했다. 평균80 목표는 미달이다. 아래의 두 구간 수선77.25는 이전 저장 후보 조합 기록이며, 주변 영역 보존 조합77.25와도 다른 평가다. 서로 혼합하지 않는다. 최신 전체 결과는 문서 마지막 절을 확인한다.

## 두 구간 동시 재연결

기존 짧은·긴 구간 수선은 하나씩 좋아지는 변경만 수용했다. 실제 두 구간을 함께 바꿀 때 전체 길이·반복·편차·급회전의 상호작용으로 개선되는지 별도 실험했다. 배치를 고정하고 실제 도로 대체만 생성하며, 같은 간선 집합의 출발점·방향 변경으로 점수만 오른 경우는 개선에서 제외했다. 새 경로의 출발점은 원본 그림 첫 점에 가장 가까운 실제 노드, 방향은 그림과 동일하게 맞췄다. 점수 높은 출발점을 검색하지 않았다.

|---|---:|---:|---:|---|
| v1 제한 pilot | 4 | 72.75→72.75 | 72.729916→72.770715 | 대체 후보 12~19개로 적었음 |

| v2 원래 전체 | 12 | 77.1667→77.1667 | 77.133038→77.191378 | 실제 경로 3개 미세 개선, 약 15.5초 |
| v3 공정한 배치 보정 후 원래 전체 | 12 | 77.1667→77.25 | 77.133038→77.194829 | 강남 고양이 75→76, 아래 제약 재검증 |

v2는 사례당 실제 대체 cap64, routing cap128, 정밀 pair cap512다. 동일 창에서 찾은 경로에 비용 다양화를 적용하지만 이 비용은 원래 점수식에 넣지 않는다. 모든 창은 원래 경로의 오차·위치에서 자동 생성하며 사례별 수동 구간은 주입하지 않았다. v2 전체에서 두 단일 변경은 각각 나쁘지만 둘을 함께 바꿔 좋아지는 사례는 없었다. 따라서 ‘단일 greedy의 장벽을 해결했다’는 결론은 지지되지 않는다.

v3는 원래 경로와 v2 새 경로에 동일한 최대128 배치 평가 예산·같은 조기 종료 규칙을 적용했다. 각 배치에서 출발점과 방향을 기하학 규칙으로 다시 맞춘 뒤 정밀 원식으로 비교했다. 원래 경로에 적용한 보정은 원점수를 유지했다. 새 강남 고양이는 75.404092→75.537943으로 올라 표시 76점이 됐다. 단독 경로 보정과 실제 간선 변경의 기여를 분리했다. v3의 12조건 표는 v2 전체의 강남 하트 미세 정밀 개선까지 합친 합집합은 아니다.

## 회전 탐색 불일치: 다음 검증

전 방향 global 배치에서는 뒤집힌 하트·고양이도 탐색하지만, 블록의 `matchShape`는 해당 그림의 최초 맞춤±45°·ICP±50°를 제한한다. 넓은 회전 seed로 만든 고리를 다시 제한된 방향으로 맞춰 일부 후보를 놓칠 가능성이 있다. 이는 기존 표시 의도와 기하학 탐색의 차이이며 아직 품질 개선 근거가 아니다.

`loops.ts`와 `loopSearch.ts`에 선택형 `fullRotation`을 추가했다. 기본은 false여서 앱의 기존 방향 제한은 유지한다. 원래 점수식·원본 그림을 변경하지 않았다. 같은 seed·예산으로 기본 제한과 전 방향 맞춤을 비교하는 실험을 진행한다. 회전한 그림이 지도에서 사람이 알아보기 쉬운지는 기하학 평균과 별도 평가해야 한다.

이후 검증 결과: 저장 최고를 시작 후보로 보존한 3조건의 control/full 최종 점수는 75/71/76으로 같았다. 새 생성 pool 최고는 광안리 하트73→75, 광안리 고양이69→70, 강남 고양이72→73으로 개선됐지만 기존 최고를 넘지는 못했다. 합성150도 하트·고양이의 fit은 전 방향 옵션에서 정확히 복원되고 기본 옵션은 기존 제한을 유지했다.

저장 최고·수동 seed 없이 동일 자동 파이프라인으로 원래12조건 전체를 평가한 평균도 **76.8333으로 같았다**. 광안리 하트74→75, 별72→71이 상쇄됐고 나머지는 같았다. 실패0, 전체 기록 시간318.493초다. 이전549.406초와 실행 부하·캐시 상황이 같다고 입증하지 않았으므로 속도 개선의 인과 근거로 쓰지 않는다. 전 방향 fit은 최저 표본 잔차를 선택하므로 원래 점수식의 최고 후보를 보존한다는 보장은 없다. 기본·전 방향 fit과 기존 quick 후보를 함께 보존하고 정밀 원식으로 선택하는 후속 실험을 진행한다. 추가 fit·seed 수에 따른 계산량 증가를 별도 기록한다.

출력은 `full-rotation-loops-20261012/pilot-results.json`과 `controlled-full-rotation-20261012/results.json`이다. 후자는 분모12이고 전 방향 블록 fit 외에는 기존 자동 파이프라인과 같은 단계·수치 설정을 사용한다. 코드의 원본 바이트 스냅샷을 보존했으며 파일별 hash를 확인한다.

## 잔차 대신 원식 선택, 후보 보존의 추가 진단

`shapeFitHypotheses.ts`는 실제 고리를 고정하고 48개 cyclic 대응의 균일 Procrustes 배치를 다양하게 비교한다. 반사·비균일 변형은 하지 않는다. 원래 최고 4개 어려운 경로에서는 대응점 배치를 여러 개 시도해도 최고 점수가 오르지 않았다. 최저 잔차 배치가 원식 최고가 아닐 수 있다는 가설은 확인됐지만 현재 최고 경로의 병목을 해결하지 못했다.

다른 실제 고리에서도 확인했다. 기본·전방향 생성 pool의 144후보를 검증하고 간선 집합으로 중복 제거하여 124개 실제 고리를 비교했다. 단일 fit과 여러 fit의 최대 후속 보정 cap은 각각256과2×128이었으나 실제 보정 횟수는9,516→23,355였다. 73개 고리에서 여러 fit의 원식 점수가 더 높았지만 원래 최고를 보존한 최종3조건은75/71/76으로 같았다. 새 방식의 우위를 단순 cap 같음으로 주장하면 안 된다. `shape-fit-hypotheses-20261012/results.json`, `shape-fit-pool-20261012/results.json`에 원점수·비용·해시·한계를 기록했다.

기본 방향 fit과 전방향 fit을 모두 평가하는 dual-loop 첫 시험도3조건 최종 점수를 올리지 못했다. 약2.8배 실행 비용에 추가 최고 품질이 없었다. 기존 default 자연고리→default 배치 순서를 먼저 끝내고 확장 후보를 추가하는 보존 순서 검증을 이어간다. **고리 후보 집합을 보존해도 전체 pipeline 보존을 보장하지 않는다.** 후보가 늘면 top8 보정·top4 순서 탐색에 기존 잠재력 높은 후보가 밀려날 수 있다. 원래 pipeline을 끝까지 실행한 최고를 보존한 뒤 추가 탐색하는 비교가 필요하며 합산 비용을 명시해야 한다.

보존 순서를 보정한 dual v2도 완료했다. 실제 세 조건에서 기본 후보의 정확한 포함과 phase0 정밀점수 일치를 모두 검증했지만 최종 표시 점수는75/73/71로 유지됐다. 기본 약59.8초, 확장 약170.2초였고 추가 평가량을 기록했다. 실제로 별의 기본 방식 후속 보정 정밀점수72.576010보다 dual의72.562725가 낮아, top8 단계에서 잠재력이 있는 후보가 밀릴 수 있다는 현상이 관찰됐다. 따라서 후보 집합의 포함 검사만으로 전체 결과 보존을 주장하지 않는다. 앱의 방향 기본값은 변경하지 않았다.

## 도로 입력부터 실행하는 단일 자동 cascade pilot

기존 자동 탐색을 끝까지 완료한 뒤 최종 최고를 보존하고, 상위3 실제 경로의 면 beam → 최고 경로의 긴 구간 재연결 → 두 구간 재연결 → phase-aware 균일 보정128을 추가했다. 저장 최고나 수동 배치 seed는 읽지 않았다. 기존 cold 본문이 원래 controlled 하네스와 동일한지 정규화된 문자열로 확인하고 코드·도로·설정 해시를 실행 전에 기록했다. 예산은 추가되므로 동일 비용 실험이 아니다.

독립 `tests/eval/offline-cascade-audit.test.ts`는 검색·수정 없이4조건의 cold·최종·출력pool 총103후보를 정확7자리 유일 좌표 대응과 실제 노드 좌표 일치로 재구성하고, 실제 간선·폐곡선·3~8km·반복≤.2·경로/그림 영역·원식 점수·최종 canonical phase를 확인했다. 감사 테스트와 lint가 통과했다. 결과는 같은 폴더의 `independent-exact-audit.json`이다. 후속 전체12조건 평가를 이어간다.

## 자동 coarse 면 population의 제한 실험

자동 coarse 배치12개×임계값3에서 면 집합과 균일 배치를 함께 바꾸는 prototype을 두 조건 각500상태로 평가했다. 광안리 고양이·서면 별의 기존71/72를 보존했지만 신규 최고48/67로 넘지 못했다. 초기36상태 중 유효35/33으로 초기 거리 제한이 주요 실패 원인이라는 근거는 약했다. 낮은 점수 자식 유지1/0회여서 비개선 중간 상태 연쇄를 충분히 탐색했다고 주장할 수도 없다. 후속은 자동 cold pool의 실제 좋은 부모와 명시적 다양성 reservoir를 구분해 검증한다. 기존 결과를 보존하며 공유 평가식이나 앱을 바꾸지 않는다.
