# 실제 드로잉런과 현재 패턴 탐색의 괴리·평가 설계

조사일: 2026-10-21. 역할: AI 전문가 토의의 비판·평가 담당. 코드와 저장 보고서는 읽기만 했고, 새 탐색·실제 API·학습·holdout-v2 평가는 실행하지 않았다. 공개 완성작과 작가의 설명을 현재 앱의 성능 측정으로 바꾸지 않는다.

## 1. 실제 작품의 제작 방식과 현재 코드 사이에서 확인되는 차이는 무엇인가?

### Takeaway

실제 창작자의 핵심 특징 우선 계획과 도로 맞춤은 현재 방식과 일부 겹친다. 차이는 단순한 ‘LLM 유무’나 ‘여러 획 지원 유무’보다 **어떤 도로 구조를 남기고, 어느 단계에서 인식 가능한 후보에 계산을 쓰며, 실제 이동과 그림을 어떻게 표현하느냐**에 있다. 공개 완성작은 선별된 사례이고 장거리·장소 선택·기록 방식이 달라 현재 고정 영역의 3–8km 과제보다 쉽거나 어렵다고 단정할 수 없다. ## 2. 기존 지표로 무엇을 알 수 있고, 무엇을 새로 측정해야 하는가?

### Inferences

평가 누수와 오해를 막는 원칙:

1. 생성 모델이 경로에 맞춰 만든 참고 그림을 다시 기준으로 삼아 ‘80점’이라 하지 않는다. 모델의 observed part는 실제 arc ID/범위에 대응시키고 imagined/missing part를 따로 기록한다. 그러나 arc 대응이 정확해도 의미 해석은 독립 사람이 검증한다.
2. GPT 생성·GPT 판정 결과는 상관 오류가 있을 수 있다. 다른 에이전트라는 이유만으로 독립 인간 평가로 바꾸지 않는다. VLM은 디버깅용 보조 결과로 구분한다.
3. 유명 작품의 이름·제목·캐릭터 참조·장식·지도 지명을 자유 명명 입력에서 숨긴다. 사람이 먼저 원본을 보고 적은 답을 잠근 뒤 이름을 공개한다.
4. 비교에서 max 거리·ROI·반복률·graph detail·표시할 획·총 시간·AI 모델/호출 수 중 어느 것을 바꿨는지 모두 기록한다. 조건을 넓힌 결과는 별도 과제로 보고 원래 strict 평균과 섞지 않는다.
5. 의미 평가의 ‘일치’는 생성자가 정답을 정하는 방식보다 독립 사람들의 의미 범주 합의와 생성 이름의 일치를 함께 본다. 동의어 묶기 규칙을 방법명 공개 전에 정하고 애매한 사례는 유지한다. 꽃↔장미는 상위 범주 합의와 구체 명칭 합의를 분리하고, 고양이↔토끼는 ‘대상으로 읽힘’과 모델의 세부 이름 정확성을 구분한다. 글자·숫자·기호도 별도 범주로 둔다.
6. `none`·안전 거절·유효 경로 없음·시간 초과·API 오류는 서로 다른 상태다. 성공률 분모는 고정 요청 수이며 아무것도 추천하지 않은 요청을 제거하지 않는다.
7. 이미 생성 이름과 판정을 본 여섯 시제품은 개발·오류 분석 자료다. 이를 다시 독립 테스트로 부르거나 같은 입력을 train/test로 나누지 않는다. 새 지각 확인 query는 기존 strict의 holdout-v2와도 별도로 동결하며 서로 대체하지 않는다.

### Gaps

- 사람의 ‘뭘 닮았는지’는 단일 정답이 아닐 수 있다. 소수 pilot에서 합의·평정자의 불확실성·대안 명칭을 남겨야 하며 현재 데이터로 사람 인식 80% 임계값을 정할 근거는 없다.
- 연속 외곽선의 기하학 80과 자유 인식 성능 중 어느 쪽을 제품의 우선 출시 기준으로 할지는 별도 제품 결정이다. 두 목표의 성과를 서로 대신하지 않는다.
- 단순 raw pool 크기·특징 coverage·모델 cosine이 사람 인식 향상을 보장하는지 미검증이다.

## 3. 최소 실험과 알고리즘 전문가 토의의 합의안은 무엇인가?

### Takeaway

바로 거대한 새 모델을 학습하기보다 **고정 후보 풀의 선택 실험 → 부분·관계 기반 생성의 동등 예산 실험 → 아직 보지 않은 지역 확인** 순서가 비용과 해석 가능성 면에서 적절하다. 이것은 실행 전 계획이며 성능 개선·원래 평균 80 달성을 뜻하지 않는다.

### Cited Findings

- GPS art 경로 생성 연구도 수작업 계획을 줄이는 것이 문제임을 명시한다. 연구 제목·자동화 개념만으로 현재 앱의 발견형 성능을 증명할 수는 없다. [Waschk·Krüger 2019, 원 논문 초록](https://www.sciopen.com/article/10.1007/s41095-019-0146-z)
- 기존 프로젝트의 후보 생성·평가·명명을 분리하라는 인계와, 공개 작가의 핵심 부분 우선 계획이 새 실험의 직접 근거다. [인계의 핵심 결론](</C:/Users/ekdus/OneDrive/바탕 화면/running/docs/recognition-route-handoff.md:21>), [Gene Lu](https://genelu.com/work/gps-art-running)
- 고정 12의 원식·원본·범위·실제 연결·holdout-v2를 유지해야 하며, 알고리즘 선택 전에 holdout-v2를 열어 튜닝하지 않는다. [최신 인계:344](</C:/Users/ekdus/OneDrive/바탕 화면/running/docs/recognition-route-agent-handoff.md:344>)

### Inferences

#### 최소 실험 프로토콜 제안

1. **먼저 조건 동결.** 현재 커밋, 도로 스냅샷, graph 설정, ROI, 거리, 시작점, budget, native ID, renderer, 모델 버전·프롬프트·후보 선택·검증 규칙을 해시와 함께 보존한다. 기존 원래 12·holdout-v2 파일은 열거나 변경하지 않는다. 새 발견형 개발 세트와 독립 확인 세트는 서로 떨어진 지역으로 새로 추출한다.
2. **소규모 pilot 6요청 + 동결 확인 6요청.** 예를 들어 격자 시가지·불규칙 시가지·공원/하천 인접의 세 도로 형태에서 각 두 요청을 개발용으로 고르고, 별도 지역에서 동일 층화 여섯 요청을 잠근다. 잘 나온 도로만 사후 선택하지 않고 지역·ROI 생성 규칙을 결과 전에 정한다. 표본 12개는 방향 선택용 최소 pilot이지 보편 성능 인증 표본이 아니다. 원래 strict와 별개로 각 요청 거리 3–8km와 현재 앱 예산을 유지한다.
3. **선택기만 비교.** 같은 최초 raw 후보 풀에서 A=현 fingerprint/다양성, B=실제 선에서 지지되는 특징·부분 관계+다양성으로 최종 세 개를 고른다. API 호출 수·모델·그림 표현은 같게 한다. 후보 추가 없이 좋아지면 선정 병목의 근거다. 풀 안에 사람 인식 후보가 거의 없으면 선정기 튜닝을 길게 반복하지 않는다.
4. **후보 풀 감사.** pilot은 가능하면 실제 raw pool 전수를 사람이 판정한다. 부담이 크면 각 arm의 사전 고정 최대 12개와 모델 무관 12개 등 동일 규칙의 제한된 합집합을 감사하고, 이를 ‘전체 oracle’로 부르지 않는다. 생성 → 유효성 → screening → 최종3 → 명명 단계마다 후보 수, 탈락 사유, 사람이 알아본 후보의 잔존률을 기록한다. rare motif를 알고리즘이 버렸는지 생성조차 못했는지 분리한다.
5. **새 생성은 그 다음.** A=현재 생성, B=chain/motif를 부분·관계 그래프로 보존한 생성, 후단 선택기는 같게 놓는다. 총 시간·실제 확장/평가 수·최대 AI 후보3·API 비용 상한을 같게 하고 느린 전처리도 포함한다. 동일 최대 cap뿐 아니라 실제 소비 비용을 기록한다. 이후 pilot에서 정한 규칙을 동결하고 독립 확인 6요청에는 한 번만 적용한다.
6. **표현 변경을 별도 arm으로.** 원시 graph의 단말 보존, 교차·가지, 여러 획·connector를 허용하면 현 strict와 다른 발견형 표현이다. 그림 획과 실제 이동은 각각 보관하고, 실제 총 이동거리와 모든 연결부를 검증한다. 중단 중 우회나 비도로 직선을 원래 12에 섞지 않는다. 화면에서 connector를 감췄다면 전체 이동 그림을 본 평가도 별도로 기록한다.
7. **사람 평가 세 단계.** 각 후보를 무작위 방법명·이름·점수 없는 동일 크기 실제 선으로 제시하고 자유 명명과 명확성·none을 잠근다. 다음 단계 이름만 공개해 동의·부족한 특징을 묻는다. 마지막으로 참고선·꾸밈선을 공개해 이해 도움과 실제 경로 혼동을 묻는다. 세 명 이상 독립 판정자를 사용하며 동의어·합의 규칙과 해시를 사전 고정한다. 꾸밈의 순수 인과 효과가 필요하면 마지막 단계에서는 별도 사람 그룹에 이름만/이름+꾸밈을 무작위 배정한다. 단일 순차 평가의 점수 상승을 인과 효과라고 부르지 않는다.
8. **판정.** 주 지표는 유효 코스의 원본 `query yield@3`와 잘못된 명명률이다. 개별 후보 분석은 요청·지역 단위로 묶어 대응 차이와 불확실성을 보고하고, 출력 없음도 분모에 둔다. p95 지연·접근거리·총 이동·반복·API 오류·none 비율이 악화되는지도 함께 본다. 최소 표본에서는 ‘유망/미개선/추가 자료 필요’로 판단하고 80% 성공을 선언하지 않는다.
9. **기하학 작업의 별도 회귀.** 새 방식이 기존 그림 지정 경로에도 영향을 주면 원래 12를 cold 실행·정밀 감사한다. 새 발견형 성과와 원래 77.416667을 별도 보고하며, 원래 평균80과 독립 지역 검증을 실제로 통과하기 전 완료로 기록하지 않는다.

#### 알고리즘 전문가와 주고받은 반론·수정

- 알고리즘 담당의 초기 가설은 ‘고리 완성 전 실제 chain/motif를 부분·관계 graph로 남겨 귀·몸통·꼬리의 위치 관계를 도로에서 동시에 지지시키자’였다. 평가 담당은 이미 branch/group이 있으므로 새로움이 복수획 자체가 아니며, 현재 graph가 제거한 실제 가지를 새 추론 모델이 복구할 수 없다고 지적했다. 합의는 기존 기능을 재발명하지 말고 **표현 지원률과 후보 생존률을 먼저 측정**하는 것이다.
- 평가 담당은 특징점 coverage가 이미 1인 엄격 평가도 미달이므로 ‘귀 검출 bit 몇 개’로 개선을 보장할 수 없다고 반론했다. 합의는 부분의 상대 위치·비례·연결·원본 선 지지와 전체 윤곽을 같이 다루되 독립 사람 평가로 확인하는 것이다.
- 평가 담당은 새 참고 그림을 경로에 맞춰 그린 뒤 그 그림과의 일치로 성공을 판정하면 자기검증 누수라고 지적했다. 합의는 observed part의 native arc 근거를 보존하고 imagined/missing 부분을 분리하며 원본 자유 명명을 주 결과로 삼는 것이다.
- 알고리즘 담당은 지지 subgraph 내에서만 닫힌 이동을 만들 때 반복 하한을 논할 수 있지만, 더 넓은 실제 graph의 새 connector를 허용하면 추가 길이가 곧 반복 길이는 아니라고 정정했다. 합의는 임의의 반복 하한으로 후보를 탈락시키지 않고 실제 방문 multiplicity와 필요한 연결을 검증하는 것이다.
- 양측은 첫 실험을 고정 풀 selector 비교로 수정했다. 공개 작품만 보고 ‘좋은 모양은 모두 여러 획’이라고 일반화하지 않고, 도로 우선·그림 우선 두 모드를 유지한다. 새 생성 효과와 이름·꾸밈선 효과를 별도로 검증한다.

### Gaps

- 아직 이 계획의 표본·사람 판정·API 사용량은 생성하지 않았다. 명명률·평균 유사도·개선 폭에 대한 새 수치는 없다.
- 좋은 공개 작품이 어떤 탐색 예산으로 발견됐는지, 실패한 초안이 얼마나 있었는지 대부분 알 수 없다. 그런 완성작 모음만으로 추천 시스템의 성공률이나 전 지역 coverage를 계산할 수 없다.
- 실제 GPX를 받더라도 사람 작품의 지도 스냅샷·이동수단·거리·접근·중단 조건이 현재 DB와 다르면 현재 도로에 정확히 매칭되는지부터 감사해야 한다. 작품 점수 재현은 이후 자동 발견 실험을 대신하지 않는다.
