# 관계 가설 기반 경로 생성: 개발 실험 및 독립 검증 규칙

2026-10-21. 실행 전 평가 원칙 제안이다. 실제 실행 결과와 최종 구현의 차이는 별도 실행 보고서에 기록한다. `recognition-solution-review-20261021.md`의 다음 단계인 **고정 가설을 따른 실제 도로 수선**을 평가하며, 유동적인 의미 가설 생성 시스템의 완성이나 인간 인식률을 검증했다고 해석하지 않는다.

## 고정 조건과 비교

- 이미 사용한 개발지역 `daejeon-dunsan`, `daegu-center`, `seoul-songpa`를 사용한다. 디렉터리 이름이 `holdout`이어도 이번에는 개발 자료다. `holdout-v2`는 읽지 않는다.
- 지역별 동물 슬롯 1개와 사물 슬롯 1개, 총 **6조건**을 고정한다. 가설 ID는 수선 전에 결정·저장하며, 결과가 나쁘다고 다른 대상으로 교체하지 않는다. 단순 윤곽 슬롯을 추가하면 총 9조건의 별도 실험으로 선언한다.
- 동일 도로 해시·그래프 `simple`·계단 제외·영역·초기 풀·난수 seed를 모든 비교에 사용한다. 초기 풀은 fresh 자동 생성한다. 기존 실험 저장 최고 경로를 읽어 초기화한 결과는 별도 warm-start 실험으로만 보고한다.
- 수선 단계 예산 **0/8/32/96**을 비교한다. 0은 동일 초기 경로의 무수선 대조군이다. 가능한 경우 하나의 결정적 제안 순서에서 prefix 결과를 저장하여 작은 예산이 큰 예산과 같은 시작을 갖도록 한다. prefix가 아닌 독립 재실행이면 명시한다.
- 새로운 seed로 재현성을 확인한다면 사전 지정한 동일 seed 목록 전부를 보고한다. 점수가 높은 seed만 골라 대표 자동 성능으로 사용하지 않는다.

## 공정한 비용 기록

단계 수는 CPU 시간이 아니다. 각 조건·예산에 대해 초기화 시간, 가설 선택 시간, 수선 시간, 총 wall time, 가능하면 process CPU user/system 시간을 따로 저장한다. 실제 routing 호출 수·노드 확장 수·평가 후보 수·유효 후보 수·채택 수를 함께 기록한다. 동일 8단계라도 구현별 내부 탐색이 다르면 동일 연산량 비교라고 부르지 않는다.

증분 8→32→96 비용과 fresh end-to-end 누적 비용을 구분한다. 저장 캐시를 읽은 소요시간은 cold 생성 시간으로 쓰지 않는다. 선택기 대조군과 수선 생성기가 동일 계산량이 아니라면 **추가 계산을 사용한 전후 비교**라고 명시한다. 외부 API는 호출하지 않는다.

## 유효성 독립 확인

선택 경로를 도로 그래프에서 다시 읽어 아래를 확인한다. 생성기가 반환한 `valid` 필드만 신뢰하지 않는다.

1. 모든 연속 노드가 실제 도로 간선으로 연결되고 시작점=끝점이다.
2. 경로와 균일 배치한 기준 그림이 해당 원래 영역 안에 있다. 이동·회전·균일 크기 조정만 허용한다.
3. 실제 간선 길이 합이 3,000–8,000m이고 무방향 간선 중복 길이/총길이가 0.2 이하다. 표시용 반올림 값으로 경계를 판정하지 않는다. 기존 하네스가 투영 거리도 검사했다면 그 조건도 동일하게 유지한다.
4. 변경 전후 무방향 간선 집합과 실행 순서를 비교한다. 같은 간선의 순환 시작점·방향만 바뀐 것을 새 경로 생성으로 세지 않는다.
5. 가설 점수·전체 편차·최악 연속 구간·새 관계 항목을 최종 경로에서 독립 재계산한다. 명시적 해부학 관계가 없고 윤곽 구간의 편차만 사용했다면 **관계 대리 지표**라고 부른다.

유효 초기 경로가 없는 조건도 삭제하지 않는다. 유효성 실패는 기하학 성과 0점/자유 인식 실패로 남기며 평균 분모는 항상 6(또는 사전 고정한 9)이다. 대조군의 유효 후보는 보존하고, 제약을 위반한 새 후보로 교체하지 않는다.

## 두 가지 성능을 분리

**기하학·수선 성과:** 조건별 원래 `evaluatePath` 정밀/표시 점수, 새 가설 오차, 제약 통과, 실제 간선 변경 수를 보고한다. 새 가설 오차의 단조 개선은 탐색 목적함수 개선이며 알아보기 쉬워졌다는 증거가 아니다. 새 가설 은행이나 지역의 평균은 광안리·서면·강남 × square/heart/star/cat의 **원본 고정 12조건 평균 77.416667**과 직접 비교하지 않는다. 원본 12조건 점수식·그림은 변경하지 않는다.

**원본 자유 명명:** 기준 그림·가설 이름·방법·점수를 가린 동일 선 굵기/여백의 실제 경로 PNG만 제시한다. 평가자는 `name|none`, 명확/약한 연상/없음, 실제 보이는 특징, 상상해야 하는 특징을 기록한다. 기본도형과 사물·동물 인식을 구분한다. 가설을 알려주고 관계를 확인하는 평가는 자유 명명과 별도이다.

모든 예산의 그림을 무조건 평가하는 대신 사전 선택한 0·최종 예산의 고정 전 조건을 같은 판정 기준으로 비교할 수 있다. 동일 그림은 해시로 중복 제거하되 각 방법의 고정 분모로 환산한다. 원본 선만 보고 난 뒤에야 기준 그림을 공개한다. 같은 모델 계열 AI 평가라면 사람·타 모델의 독립 평가라고 표현하지 않는다. 기존 판정 재사용은 새 판정과 분리한다.

권장 대조 그림은 기존 사람이 만든 단순 윤곽/부분 구조 양성 사례와, 부분 위치 교란/필수 구간 훼손/긴 여분 돌출 음성 사례다. 대조 그림은 도로 경로 성과 분모에 넣지 않고 평가자 민감도 점검으로만 기록한다. 제작자의 제목을 숨기지 못했으면 맹검으로 부르지 않는다.

## 최적화 가능 범위의 표현

8/32/96에서 얻은 최고점과 한계 비용을 그래프로 정리하고 개선이 어느 예산에서 줄어드는지 설명한다. **이번 구현·개발지역·고정 seed·예산에서 관측한 도달점**이다. 96단계 정체는 전역 최적·도로의 불가능성·모든 모델의 성능 상한을 증명하지 않는다. 유효 경로가 있어도 의미 인식이 실패하면 이를 실패로 보고한다. 원본 인식 개선이 없을 때 앱 기본을 바꾸지 않는다.

## 참조한 코드와 자료

- `tests/eval/hypothesis-pilot-20261021.test.ts`: 동일 fresh 도로 풀·방법 분리·원본 PNG 렌더·해시 검증의 출발점.
- `tests/eval/route-parts-pilot.test.ts`: 지역별 실제 간선/투영 거리/반복 이중 검사 및 동일 후보 풀 비교.
- `tests/eval/pair-segment-repair.test.ts`: 실제 간선 교체와 순환 시작점 변화 구별, 입력·자료·코드 해시 기록의 참고. 기존 저장 최고 경로 warm-start를 이번 fresh 실험에 그대로 이전하지 않는다.
- `src/lib/route/repairRoadPath.ts`: 기존 국소 수선·원래 목적함수의 참고이며, 의미 관계 인증을 수행하는 구현은 아니다.

2026-10-21 최종 파일 동결 후 `tests/eval/relation-generation-audit-20261021.test.ts`를 실행했다. `RELATION_AUDIT_RUN`에 다음 여섯 실험을 지정했으며 **모두 통과**했다.

| 실험 | 초기·출력 상태 수 | 추가 pose-only 대조 상태 |
|---|---:|---:|
| trial-v1 | 42 | 0 |
| extended-fixed-v1 | 30 | 0 |
| extended-v1 | 30 | 0 |
| hybrid-v1 | 54 | 0 |

총 **288상태**는 반복된 초기 상태를 포함하며, 고유 경로나 독립 표본 288개라는 뜻이 아니다. 고정 6조건 ID, 후속 실험의 같은 초기 경로·배치·대상, 도로 해시, 실제 간선·닫힘·영역, native/투영 거리와 반복률, 원래 점수식의 정밀 재계산을 검사했다. 고정 배치의 간선 변경 결과가 원본과 순환 시작점 정규화 대조 모두보다 엄격하게 좋은지도 확인했다. 배치 변경이 포함된 결과는 간선 변경 효과와 구분하여 최종 배치에서의 대조 점수를 기록했다.

최종 여섯 감사 파일의 현재 소스 해시 불일치는 모두 0이다. 실행 중 stress 산출물이 교체되던 순간의 일시적인 결과/스냅샷 불일치는 최종화 후 재감사에서 해소됐다. 감사 결과는 `eval/recognition/relation-generation-20261021/audit-{run}.json`에 저장했다. 이 감사는 **실제 도로 제약과 기하학 계산의 독립 검증**이며, 의미 인식 향상이나 앱 품질의 검증을 대신하지 않는다.
