# 부분 배치를 반영한 후보 선택 1차 적용

후속 검증: 명확한 인식 개선이 확인되지 않아 앱 기본을 `baseline`으로 복구했다. 아래는 최초 적용 당시 기록이다. 현재 상태와 재분석은 [검증 보고서](structure-selection-validation-20261021.md)를 따른다.

2026-10-21. 추가 30작품 조사에 따라 발견형 추천의 서버 AI 입력 후보 선택을 변경했다. 기존 자연 폐윤곽 생성, 실제 도로, 거리·반복 제약, 원래 평가식은 유지한다. 내부선·가지 생성이나 사물별 부분 검출을 구현한 것은 아니다.

## 변경

- 기존 선택기의 첫 후보는 유지한다. 단순 윤곽을 배제하지 않는다.
- 두 번째는 큰 돌출·오목 구조가 나타나는 후보를 우선한다. 호 길이 64표본과 원형 평활화 후 중심으로부터의 상대 반경 변화를 사용하며 미세 꺾임 차이는 감점한다.
- 세 번째는 앞선 후보와 부분의 상대 크기·호 간격이 다른 후보를 고른다. 순환 이동·역방향을 비교해 출발점과 진행 방향에 따른 차이를 줄인다. 위치·균일 크기·회전에 의존하지 않는 표현이다. 표본화 때문에 임의 출발점 변경에 대한 완전한 불변성은 보장하지 않는다.
- 같은 후보 풀·최대 3개·기존 API 모델과 출력 한도를 유지한다. 추가 외부 호출은 없다. 기존 이름·유사도는 선택에 사용하지 않는다.
- `selectRoadReferenceInputs`의 네 번째 인자 `baseline`으로 기존 선택을 재현할 수 있다. 기본은 `structure`다.

## 동일 저장 후보의 확인

기존 실제 도로 6개만 입력했다. baseline은 road-06/02/01, 변경 후는 road-06/03/02다. 첫 후보가 보존되고 한 후보가 교체됐다. 사전에 골라 저장한 6개인 만큼 전체 운영 후보 풀이나 독립 검증 지역을 대표하지 않는다.

단일 실행 선택 시간은 baseline 17.69ms, structure 8.87ms였다. 워밍업·실행 순서가 달랐고 두 방식 모두 새 특징을 계산하므로 속도 개선 비교가 아니다. 외부 호출은 0이다. 재현 결과는 Git 제외 `eval/recognition/structure-selection-20261021/comparison.json`에 저장했다.

## 검증과 한계

회전·진행 방향·직선 구간의 점 밀도 변화, 큰 오목 구조 구별, 퇴화 입력, 첫 후보 보존·후보 순서 독립·3개 제한을 검증했다. 기존 클라이언트의 익명 입력·실제 경로 보존·보류·실패 대체 검증도 유지한다.

구조가 복잡하다고 알아보기 쉬운 것은 아니다. 길쭉한 도형도 높은 반경 변화를 보일 수 있다. 이 값은 사물 인식 점수나 사람 인식률이 아니다. 같은 후보 선택에 대한 최초 구조 휴리스틱이며, 별도 의미 평가 전 품질 우위를 확정하지 않는다. 기존 12조건 평균 77.416667이나 80점 목표 달성의 새 측정값도 아니다.

다음 품질 비교는 이름·꾸밈선을 숨긴 원본만으로 baseline/structure의 합집합을 평가하고, 동일 후보·3개 호출·동일 모델·동일 총 예산에서 판정해야 한다. 이 단계에서 이득이 없으면 복잡도를 더 높이기보다 선택 기준을 수정하거나 되돌린다. 후보 풀에 필요한 부분 구조가 없는 경우에만 내부선·가지 생성 실험을 별도로 진행한다.

재현: PowerShell에서 `$env:ROUTE_STRUCTURE_EVAL='1'` 설정 후 `npx vitest run tests/eval/route-structure-selection.test.ts`. 기존 도로 입력 audit 파일이 없으면 해당 비교는 건너뛴다.
