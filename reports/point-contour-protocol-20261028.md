# 점 조건부 윤곽 복원: 사전 계획 v1

2026-10-28. 단독 수행. 앱 기본 및 기존 고정 12조건은 변경하지 않는다.

## 질문과 범위
H1: 이름과 순서 없는 부분 점을 입력받은 모델이 미사용 원본의 윤곽을 학습 그림 검색보다 잘 복원하는가?
H2: 생성 윤곽을 기존 실제 도로 탐색기에 넣을 수 있는가? H1 성공과 H2 기술 연결 및 사람 인식 성공은 별개다.

## 고정 설계
- Quick Draw simplified 원본 apple, fish, bird. 공식 Google 공개 저장소 자료, CC BY 4.0 출처 기록. 각 종류 처음 10000행 이내에서 recognized=true, 단일 획, 8점 이상, 끝점 간격/최대변 길이 <=0.15 조건의 첫 240개까지 수집한다. 이 선택은 모든 사물의 대표 표본이 아니다.
- 닫힘을 위해 추가한 마지막 연결선 길이를 기록한다. 여러 획을 임의로 이어 외곽이라고 간주하지 않는다.
- 정규화 원본 좌표 중복 제거 후 원본 단위 seed=20261028, 70/15/15 분리. 좌표 y는 위가 양수, 최대변 1. 출력 64개 균일 호길이 점. 시작점은 가장 오른쪽 점, 진행 방향 통일.
- 입력은 균일 8점/16점 또는 무작위 16점. 입력 순서를 섞고, 원본 순서를 모델에 제공하지 않는다. 초기 실험은 정규화와 이름을 제공하는 유리한 조건이며 도로 일반화로 해석하지 않는다.
- 작은 점 집합 인코더(max+mean pooling) + 종류 조건 + 64좌표 복원기. CPU 60epoch, batch64, Adam lr0.001. 검증 오차 최저 checkpoint만 선택. 최종 평가로 튜닝하지 않는다.
- 대조군: 같은 종류 학습 원본 중 입력점→윤곽 거리 최소 검색; 중심 기준 각도 정렬 후 보간(정답 순서 사용 안 함).
- 주지표: 대칭 Chamfer 평균 유클리드 거리(정규화 단위), 보조: 입력점 거리. H1 잠정 지지 기준: 최종 평가 평균이 검색 대비 10% 이상 개선하고 세 종류 모두 악화하지 않음. 사람 인식 검증 전 의미적 성공 주장 금지.
- 원본 단위 bootstrap 95% 구간, 클래스별 및 점 누락 조건별 결과, 모든 실패 포함. 동일 원본 변형은 독립 표본으로 세지 않는다.
- 성공 여부와 무관하게 데이터 manifest, checkpoint, 결과, 원본/입력/출력 진단 화면 저장. 데이터와 모델은 gitignored eval/recognition/point-contour-20261028, 보고서와 실행기는 추적 가능 위치.

## 후속 도로 진단
기존 개발 6조건의 저장 실제 경로에서 부분 점을 추출해 입력하는 것은 기존 후보에 조건부인 기술 진단이다. 주변 도로에서 자동으로 좋은 점을 발견한 성과로 보고하지 않는다. 동일 배치·검색 예산으로 생성/검색/고정 도형을 비교하며 기존 실제 간선·3–8km·반복20% 기준 유지. 사람 평가는 미실시로 표시한다. H1 실패 시 대규모 학습보다 원인과 다음 가설을 기록한다.

도로 실행 전 구체화: 학습 종류와 겹치는 apple/bird 3조건 전부 사용(다른 3조건은 미지원 종류). 기존 경로를 호길이 64점으로 표현하고 매4번째 16점을 사용한다. 기존 배치를 역변환하며 정답 윤곽 순서는 모델에 주지 않는다. 각 방법은 orderedContourPath, bins32, guideWeight1.5, radiusFraction0.2, maxExpanded100000, 동일 기존 배치 사용. 각 윤곽 첫점의 최근접 실제 노드를 시작점으로 선택한다. 9번 요청 모두 분모에 포함한다. 이는 기존 전체 자동 탐색과의 성능 비교가 아니라 동일 탐색기의 참고 윤곽 교체 진단이다.
