# 윤곽 순서 탐색의 길이 자원 보존 가설

2026-10-13. 원래12조건 평균77.416667 목표 개선을 위한 코드 검토 메모다. 실제 실패 원인은 아직 진단 중이다.

## 확인한 구현

`orderedContourPath.ts`의 상태는 윤곽 phase와 마지막 directed edge이며 `cost`, `length`, `previous`를 상태당 하나만 저장한다. `update`는 새 비용이 작을 때만 바꾼다. 실제 길이는 상태 키가 아니며 마지막 도착 조건에서 최소 거리 이상인지 검사한다. 이 관찰은 코드 구조이며 현재 결과가 반드시 이 문제 때문에 나쁘다는 증거는 아니다.

## 검증할 가설

같은 phase·incoming edge에 도착하는 저비용 경로가 너무 짧으면, 더 비싸지만 최소 거리를 만족하는 경로를 밀어낼 수 있다. 최소 거리라는 하한 조건이 있으므로 비용이 낮다는 이유만으로 항상 유효한 지배 관계가 성립하지 않는다. 예를 들어 같은 목표 상태의2,900m 저비용 경로와3,100m 고비용 경로 중 앞의 것만 보존하면 뒤의 유효 경로를 잃는다. 이는 추상 사례이며 실제 도로에서 이런 사례를 확인해야 한다.

길이가 긴 경로가 항상 좋은 것도 아니다. 반복 구간을 더 달려 최소 거리만 맞춘 후보는 기존 반복률0.2 제약을 통과하지 못하거나 모양이 나쁠 수 있다. 따라서 길이 label 증가 자체를 품질 개선으로 주장하지 않는다.

## 다음 대조의 기준

추가 코드 확인에서 `multiLabelContourPath.ts`는 이미500m 길이 bucket을 사용한다. 각 bucket 안에는 여전히 대체 비용 한 label만 보존하며 normalized cost를 사용한다. 과거 원래12조건에서 평균76.75가 유지된 실험 기록이 있다는 전문가 검토가 있었으므로, 단순 길이 bucket 추가를 새 접근의 성과로 주장하지 않는다. 해당 과거 실험의 자료와 예산도 현재 진단과 구분해 확인한다. 이번 관찰은 원인 증거를 얻는 목적이며 기존 실패를 무시하고 같은 구현을 반복하려는 목적이 아니다.

먼저 동작이 동일한 관찰용 복제본에서 길이 때문에 거절된 목표 상태와 기존보다 비용은 높지만 길이가 다른 대안의 수를 측정한다. 반환 경로와 확장 수가 원본과 같아야 한다. 같은 원자료·자동 배치·32/64 phase·두 방향·400,000확장 규칙을 유지한다.

근거가 있으면 기존 비용식과 phase 전진 규칙을 유지한 채 길이 자원을 여러 label로 보존하는 별도 실험을 선택한다. 첫 실험에서 비용 계수, 윤곽 표현, 배치, 탐색 예산까지 함께 바꾸지 않는다. 완성 경로는 원래 평가식과 실제 간선·거리3–8km·반복0.2·원래 영역으로 검사한다. 알려진 자동 배치를 사용하는 원인 진단과 도로부터 새로 시작하는 자동 성능 검증을 구분한다.

## 실제 진단 결과와 선택

관찰48회에서 더 긴 제안이 짧고 저렴한 label에 밀린452,677건, 3km 경계를 넘는 제안이 밀린17,173건을 확인했다. 그러나 최종 phase에서 시작점에 도달한3km 미만 상태는0개였으며48회 모두 실제3–8km·반복0.2 이하 경로를 반환했다. 확장 상한 도달도0회다. 원본과 관찰 복제본의 반환 경로·확장 수·state 수는 일치했다. 따라서 이 배치에서 최소 거리 도달 실패가 병목이라는 가설은 지지되지 않는다. label 손실이 최종 모양 점수에 어떤 영향을 줬는지는 이 계측만으로 판정할 수 없다.

이번 자료는 기존500m bucket 실험을 반복할 근거가 되지 않는다. 다음 독립 실험에서는 같은 실제 완성 경로를 평가하되, 완성 경로의 원식 점수를 중간 후보 선택에 사용하는 arm과 사용하지 않는 arm을 같은 예산으로 비교한다. 이 선택은 길이 자원 가설이 확인됐기 때문이 아니라 해당 실패 설명이 지지되지 않아 원식과 대체 비용의 선택 차이를 별도로 검증하려는 것이다. 아직 효과는 미확인이다.
