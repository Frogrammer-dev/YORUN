# 전문가 검토와 다중 획 학습 적용

2026-10-29 사용자 요청으로 AI 전문가 에이전트1명과 설계/코드 검토 후 실험 학습 파이프라인을 적용했다. 앱 추천 알고리즘을 교체한 것은 아니다.

## 전문가 검토로 바꾼 것

- 단일 폐곡선 필터 제거, 원래 획 구분과 상대 위치 보존. 열린 획은 열린 채 유지하고 획 사이를 강제 연결하지 않음.
- 정답 클래스 입력 제거. 관측 획 구분과 순서가 주어진 문제라고 명시하여 도로 자동분할 문제와 구분.
- 같은 관측정보를 쓰는 보간과 잔차모델을 비교. padding은 mask로 pooling에서 제외.
- 점 하나 획이 모델 출력에서 가짜 곡선으로 변하는 결함 지적을 받아 해당 잔차를0으로 고정. 수정 후 재학습한 결과만 채택.
- 입력 코너 보존과 출력 코너 보존은 다름. 출력은 양끝만 고정하며 내부 관측 코너 통과는 보장하지 않는다.

## 자료·실행

공식 Quick Draw simplified에서 apple/fish/bird 각300개 신규 다중획 그림 수집. 기존590개ID 제외. 총900그림/3,953획, 최대21획, 획 수 제한/절단 없음. 그림단위 hash split: train640/val123/test137. 테스트629획×두희소화수준. 출처 및 스캔/필터 통계는 dataset.json에 기록. recognized는 게임 판정이며 인간 검수 아니다.

두seed17/29,30epoch, best val epoch는 둘 다21. 정답은 원본 획의32점 근사. 획별 단순 보간에 관측된 전체그림점 context를 더해 잔차를 예측한다. 모델과 보간은 동일한 획 순서를 사용하며, 순서 없는 점만에서 연결관계를 알아내는 모델은 아니다. 정답 이름은 입력하지 않는다. 기존의 라벨조건 단일폐곡선 모델과 과제/자료가 달라 직접 성능 비교하지 않는다.

## 최종 결과

| 방식 | 그림별 평균 Chamfer↓ |
|---|---:|
| 단순 보간 | 0.012489 |
| 학습 seed17 | 0.010704 |
| 학습 seed29 | 0.010524 |

전체 오차14.3%/15.7%감소. 하지만 새 클래스는 보간0.006300에서0.006887/0.006708로 악화(약9.3%/6.5%). mild 입력은0.007471에서0.008379/0.008001로 악화. sparse 입력은0.017508에서0.013028/0.013047로 개선.

짧은 획(정규화길이<.15)은 보조 진단358획변형에서 보간0.000121→모델0.001380/0.001202로 악화. 절대 오차는 작지만 짧은 세부선이 개선됐다고 주장할 수 없다. 전체평균만 보면 놓치는 문제다. 전체오차10%감소와 클래스별비악화를 모두 요구한 사전 기준은 미달. 두seed의 양끝좌표오차 최대0 확인.

**결정: 여러 획 데이터/열린 획 전처리/무라벨 학습 파이프라인은 유지. 학습 모델의 앱 기본 적용은 보류.** 내부선 보존은 표현상의 개선이며 인간 인식 개선이 입증된 것은 아니다.

## 시각 검토와 한계

테스트 클래스별 첫2그림의 원본/관측점/보간/학습 몽타주를 확인했다. 사과 곡률 등은 복원이 나아 보이는 사례가 있지만, 물고기 몸통이 얇아지는 실패와 세부선 이동도 있다. 대상명을 아는 AI 진단이며 사람평가가 아니다. 웹 비교에는 첫4개씩12그림을 고정 공개한다.

평가는 원본그림 자체가 아니라32점 근사 기준이라 작은 특징이 전처리에서 사라질 수 있다. 코너 선택도 이 근사에 기반한다. exact hash/ID만 겹침을 검사했으므로 유사 그림·획 순서만 다른 그림까지 차단한 것은 아니다. 훈련은 획별균등, 검증/테스트는 그림별균등이라 많은 획의 그림이 학습에 더 크게 기여한다. 두seed 파일럿이며 신뢰구간/독립 사람평가/실제도로 검증 없음. 공식 Cloud2Curve도 아니다.

다음 과제는 짧은 선을 불필요하게 바꾸지 않도록 잔차를 제한하고, 관측 코너를 정확히 통과하도록 출력 표현을 바꾸는 것. 현재 테스트를 본 후 새 설정은 개발 반복임을 표시해야 하며 새로운 미사용 평가자료가 필요하다. 도로망에서 획 분할·한 경로 연결은 여전히 별도 문제다.
