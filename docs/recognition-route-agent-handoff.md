목표는 **실제 도로의 연결·거리 제약과 기존 평가식을 유지하면서 고정 12조건의 평균 기하학 유사도 80 이상을 달성하고, 새 지역에서도 검증하는 것**이다. 아직 달성하지 못했다.

시간 제한을 적용한 새 탐색은 **현재 앱에 연결되어 있다**. 운영 파이프라인은 오프라인 실험과 예산·시작 후보·대상 수가 달라 위 평균을 보장하지 않는다. 과거 보고서의 ‘앱 미적용’은 당시 실험 결과에 관한 기록이며 최신 상태는 `app-integration-20261012.md`를 읽어야 한다. `summary.json`의 상위 `appliedToApp:false`도 저장 최고 후보 합집합을 직접 적용하지 않았다는 뜻이다. 별도 `appIntegration` 항목에는 앱 연결 상태가 기록되어 있다.

핵심 결론:

1. 좋은 모양이 후보 풀에 없으면 인식 모델만 교체해도 해결되지 않는다. **후보 생성 → 입력 표현 → 인식 → 거절·순위**를 분리해 진단해야 한다.
2. DoodleNet의 높은 확신도와 사람이 경로를 알아보는 정도는 크게 어긋났다. CLIP으로 바꾸었다고 사람 인식 품질이 입증된 것은 아니다.
3. 개선의 큰 부분은 실제 도로 고리와 위치·크기·회전을 함께 탐색한 데서 나왔다. LLM이 배치만 제안하는 시도는 기준선을 이기지 못했다.
4. 영역을 크게 하면 같은 예산에서 표본 밀도가 낮아져 좋은 후보를 잃을 수 있다. 원래 후보 보존이 필요하다.
5. 별·고양이처럼 복잡한 외곽의 편차와 불필요한 꺾임이 남은 병목이다. 평균 80 미달을 숨기거나 평가 조건을 바꾸어 달성으로 기록하면 안 된다.

## 2. 사용자의 요구와 제품 개념

사용자는 실제 러닝 경로가 ‘무엇처럼 보이는지’를 추천하는 기능을 핵심으로 본다. 서버 AI 사용도 허용했으며 비용·개인정보 비교를 요청했다. 주변 동네까지 확대하는 대안도 검토하도록 허용했다.

두 작업을 구분한다.

- **발견형 추천**: 실제 동네 고리를 먼저 찾고 사물·동물·도형 이름을 붙인다. ‘아무것도 안 보임’을 정상 결과로 허용한다.
- **그림 지정**: 주어진 모양에 가까운 실제 도로 경로를 찾는다. 네모·하트·별·고양이의 고정 평가는 이 문제의 기하학 성능을 측정한다.

사용자의 꾸밈선 아이디어도 구현했다. 예를 들어 네모 경로를 토스트처럼 상상할 수 있도록 내부 특징을 보탠다. 이는 **해석을 돕는 표시**다. 실제 경로를 바꾸거나 자연 인식 평가를 높이는 수단이 아니다.

앱의 그림 지정·동네 추천은 기존 결과를 먼저 확보한 뒤 추가 탐색한다. 발견형의 개선 대상은 우선 상위 세 그림 계열이다. 여러 획 그림은 기존 `findGroupRoutes` 연결 방식을 유지한다.

모든 단계에 사용자 거리 범위를 전달한다. 기본 탐색은 영역에 따라 약 45~75초, 주변 비교는 약 75초의 공유 시간 예산이다. 단일 계산은 예산 확인 사이에 실행되므로 엄격한 실시간 종료 보장은 아니다. 순차 단계는 global → 블록 고리 → 균일 보정 → 윤곽 순서 탐색 → 최종 보정이다.

‘주변 동네도 비교’는 기본 꺼짐이다. 켜면 같은 중심에서 자료를 최대 1.8배, 한 변 15km까지 넓혀 받는다. 원래 검색 영역과 자료 수신 영역·설정 캐시를 분리한다. 원래 영역 후보를 먼저 만들고 주변 탐색에도 전달한다. 여러 획 그림에는 주변 확대를 적용하지 않는다.

## 4. 인식 모델 논의와 실제 확인 범위

### DoodleNet / QuickDraw

기존 방식은 사람의 낙서 분류기였다. 도로의 폐곡선 외곽에는 사물의 눈·다리·내부 획이 없고, 격자 때문에 모양이 다각형으로 바뀐다. 28×28 입력의 선 두께·여백·이진화·축소가 추가 정보 손실을 만들 수 있다. 이 도메인 차이를 높은 softmax 점수가 해결하지 않는다.

저장된 블라인드 평가에서 기존 낙서 명명 20개는 맞힘 0%, 기본 그림 기반 추천은 평균 35%, 그림 지정은 15%였다. **판정자는 사람 두 명이 아니라 VLM-A(Opus), VLM-B(Sonnet)** 이다. `eval/labels/blind-2026-10-10/score.md`의 진단 결과이며 인간 인식률·모델의 보편적 성능으로 보고하면 안 된다. 표본도 작고 방식별 조건이 제한되어 있다.

사용자의 실제 판정 파일 `review-pilot-20261010-성환.json`도 이전 작업에서 사용했지만 Downloads의 로컬 자료다. 현재 Git에 해당 파일이 있다는 가정은 하지 않는다. 다시 분석할 때 사람·VLM·미완료 판정 출처를 분리해야 한다.

### CLIP: 현재 앱에 연결된 방식

- 모델: `openai/clip-vit-base-patch32`. 공식 가중치를 미리 설치하고 오프라인으로 읽는다.
- 위치·크기 정규화 외곽선만 앱 서버에 전송한다. 외부 모델 API에 올리지 않는다.
- 문장: `a black line outline drawing of {english} on a white background`.
- 운영 Python은 흰 배경 896px에서 선을 그린 뒤 224px로 축소한다. 실험 PNG 렌더러와 완전히 같지 않으므로 전이 성능을 가정하면 안 된다.
- 제외 클래스도 경쟁 후보로 남긴다. 전체 최고가 허용 이름이고 cosine ≥ 0.30, 다른 모든 이름과의 차이 ≥ 0.003인 경우만 표시한다.
- 코드의 `prob` 필드에는 코사인 점수가 들어간다. **사람의 확률이 아니며 DoodleNet 확률과 직접 비교하지 않는다.**
- 96개 실제 경로 API 검사에서 16개가 거절 기준을 통과했다. 통과 16개가 사람이 알아보는 모양이라는 증거는 없다.
- 요청당 Python 프로세스를 실행하고 최대 128코스, 서버 약 80초 제한이다. 첫 모델 로딩 비용·배치 처리량·동시 요청이 개선 대상이다.
- 회전·프롬프트 안정성, 사람 평가로 보정한 출시 임계값은 아직 입증되지 않았다.

### SigLIP 2·스케치 예시 검색·서버 VLM

동결 이미지/텍스트 임베딩, 사진 대신 외곽선 스케치 예시 검색, 작은 ranking head/adapter를 후보로 논의했다. 스케치 검색 논문의 성능을 이 제품의 예상 성능으로 옮기지 않았다. 실험 장치는 `docs/recognition-lab.md`에 있으며 모델 간 공통 후보 비교를 지원한다. 현재 대안 모두의 인간 평가 우위가 검증된 상태는 아니다.

VLM은 전체 후보를 무제한 호출하기보다 상위 후보와 모델 무관 표본을 함께 비교하는 방안이다. 구조화 결과에는 이름/none, 실제로 보이는 특징, 부족한 특징, 방향을 담고 없는 눈·다리를 지어내는 것을 진단한다. 자기 confidence를 추천 확률로 사용하지 않는다.

비용은 모델 이름으로 추정하지 말고 호출 수·실제 input/output/thinking 사용량·지연·캐시·재시도로 기록한다. 예전 조사 가격은 날짜가 있는 참고이며 실행 시 재확인이 필요하다. 키를 Git·브라우저·평가 산출물에 넣지 않는다. 외곽선에서도 지역이 추정될 수 있어 위치 제거가 완전 익명화를 뜻하지 않는다.

## 5. LLM 배치 추천 실험에서 배운 것

LLM이 도로 그림을 보고 위치·크기·회전을 제안하고 기존 코드가 연결하도록 했다. 평균은 1차 63.17, 2차 64.0, flex를 제거한 고정 연결 60.67로 기준 65.75보다 낮았다.

API 키 없이 현재 대화 LLM이 작성한 제안 JSON을 평가한 실험이다. 유료 API의 특정 모델 성능이나 자동 LLM 추천 시스템의 벤치마크가 아니다. 2차는 이전 결과를 보고 수정했으므로 독립 검증도 아니다.

결론은 ‘LLM은 모두 효과 없음’이 아니라 **배치 제안만 바꾸는 이 접근의 개선 근거가 없었다**는 것이다. 다음 LLM 실험은 검증된 실제 경로 후보의 ID를 선택·해석하게 하는 것이 타당하다. LLM이 좌표·연결 간선을 직접 지어내게 하지 않고, 길이·반복·연결 검증은 코드에 남긴다. 이 다음 접근은 제안이며 효과가 입증된 것은 아니다.

## 6. 경로 생성 실험: 성공과 실패를 같이 인계

아래 숫자는 실험별 시작 후보·예산이 다르므로 한 열에서 단독 효과처럼 비교하지 않는다. 상세 계보는 `reports/route-improvement-20261011/progress.md`와 해당 결과 JSON에 있다.

| 실험 | 관찰 / 결론 |
|---|---|
| Global 배치 다양화 | 약 69.75, 전 방향 회전 약 70.33. 단순 1,200회 확대는 240회 대비 평균 개선 없음 |
| 경로 고정 + 균일 그림 보정 | 기준선 65.75 → 약 67.83. 낮은 비용으로 후보를 개선할 여지가 있음 |
| 블록 고리·면 수정·다중 시작점 | 누적 후보 품질을 크게 개선. 서로 다른 시작 배치가 다른 좋은 고리를 발견 |
| Beam 면 탐색 + refit | 낮은 중간 점수를 허용해 약 76점대 후보 확보. 저장 pool의 다양성이 중요 |

| 더 많은 coarse 배치 | 추가 개선 없음. 후보 수 증가만으로 품질을 가정하지 않음 |
| turn 가중치/정규화 cost/길이 버킷 다중 label | 일부 정밀 점수 개선, 정수 평균의 큰 개선 없음. 제한 탐색이므로 불가능성 증명은 아님 |
| Dual min-cut | 이 실험에서는 개선 없음. 구현 검증은 됐어도 품질 효과와 별개 |

| 그래프 normal 비교 | 기존 global 수준에서는 simple 대비 일관된 우위가 없었음. 원래 평가의 detail을 바꾸지 않았음 |

새 지역에서도 네모 평균 88.33, 하트 75.67, 별 72.67, 고양이 69.33이었다. 특징 커버리지는 모두 1.0인데 별 평균 편차 약 34m·급회전 3.43/km, 고양이 약 27m·3.40/km가 남았다. ‘특징점만 살리면 해결’이라고 보기 어렵다. 절대 편차만 비교해도 안 된다. 점수식에는 그림 크기의 정규화가 들어간다.

원본 그림 → 가까운 전체 도로와 원본 그림 → 선택된 경로 사이에 평균 10~14m 차이가 있는 어려운 사례가 있다. 하지만 독립된 가까운 도로들이 하나의 유효 폐곡선을 이루는 것은 아니다. 이 차이를 달성 가능한 개선 폭이나 점수 상한으로 표현하지 않는다.

## 7. 평가를 망치지 않기 위한 가장 중요한 노하우

### 원래 12조건을 보존

- 지역: 광안리·서면·강남, 각 `square/heart/star/cat`.
- 광안리 bbox: south 35.143 / west 129.100 / north 35.166 / east 129.128.
- 서면: 35.145 / 129.048 / 35.170 / 129.076.
- 강남: 37.490 / 127.020 / 37.515 / 127.051.
- `simple`, 계단 제외, 실제 도로 간선, 폐곡선, 정확한 3,000~8,000m, 반복률 ≤ 0.2.
- 경로와 배치된 원본 그림 모두 해당 영역 안. 이동·회전·균일 크기 조정만 허용.
- 실패는 0점, 분모는 항상 12. 다른 지역·모양·조건으로 교체하거나 어려운 사례를 제거하지 않는다.
- 도로 기준 시각: `2026-10-09T20:21:04Z`. 자료·코드·파라미터 해시 기록.
- `fit.ts`의 원래 `evaluatePath`와 `shapes.ts` 원본 그림을 점수 상승 목적으로 바꾸지 않는다.

### 세 가지 수치를 분리

기하학 유사도, 모델 확신도/cosine, 사람의 자유 인식률은 다른 지표다. geometric 80은 사람 인식 80%가 아니다. 저장된 실험 최고 후보 합집합과 한 번 실행한 자동 파이프라인 평균도 다르다. 평균은 조건별 표시 정수 평균인지 정밀 점수 평균인지 밝힌다.

### 반올림 필드로 목적함수를 복원하지 않기

`toCandidate`는 편차·길이·급회전·커버리지를 표시용으로 반올림한다. 여기서 정밀 objective를 복원하면 실제 더 높은 점수의 후보를 버릴 수 있다. 과거에 이 버그를 발견하고 고쳤다.

정밀 `evaluatePath` 결과 `e`를 이용하는 식:

```text
Q = meanDev / (0.08 * scale)
    + log(1 + 0.03 * zigzagPerKm)
    - log(0.55 + 0.45 * featureCoverage)
    - spikes * log(0.9)
rawSimilarity = 100 * exp(-Q)
```

작은 Q가 좋다. 길이·반복 제한도 반올림 전 값으로 확인한다. 표시 길이 5000m여도 실제 5000.02m라면 최대 5km 조건에서 제외한다. 운영 선호 순위의 penalty와 순수 기하학 성능을 구분한다.

### 폐곡선 출발점의 점수 효과

RDP와 turn 통계의 이음매 처리 때문에 같은 간선 집합도 시작 노드가 바뀌면 점수가 달라질 수 있다. 최고 점수의 이음매만 찾아 80을 달성했다고 하면 안 된다.

Anneal에서는 원본 그림 첫 점에 가장 가까운 실제 경로 노드를 시작점으로 하고 방향을 맞췄다. 원래 입력과 표준화 입력을 모두 보존하고 같은 간선 재출력의 점수 변화는 진단으로 분리했다. 실제 간선 집합이 바뀌고 두 입력보다 높은 경우만 경로 개선으로 채택했다. 후속 배치 보정 후에도 이 규칙을 다시 점검해야 한다. 모든 기존 실험·앱 후보가 이 표준화로 재평가되었다고 가정하지 않는다.

### 영역 확대·그래프 경계·거리

큰 영역은 탐색 밀도와 그래프·블록 경계가 달라진다. 넓은 그래프 안의 작은 region 탐색이 원래 작은 그래프 탐색과 같다는 보장은 없다. 기존 경로를 넓은 그래프에서 재사용하려면 정확한 노드·실제 간선 대응을 확인한다. 임의 nearest 노드 치환으로 다른 도로를 이어 붙이지 않는다.

오프라인 보존 비교에서는 12/12 exact 노드 대응·간선·동점수·길이 차이 1mm 미만 검증을 통과했다. 이것은 이번 자료의 결과이며 모든 그래프에서의 보장이 아니다. 앱의 후보 검증은 0.5m 이내 노드 검색과 실제 간선 확인을 함께 사용한다.

기록된 접근 지표는 그래프 원점 기준의 최소 경로 노드 거리, 길이 가중 중심 거리, 첫 노드 거리다. 실제 사용자 위치나 걸어서 접근하는 거리가 아니다. 일부 확대 후보는 시작점이 원점에서 직선 1.6~2.7km 떨어졌다. 품질과 접근 편의성을 같이 평가해야 한다.

### 캐시·예산·동작

거리장과 블록 캐시는 같은 그래프·정확한 region·설정에서만 재사용한다. region을 반올림한 캐시는 결과 동등성을 보장하는 키가 아니다. 앱의 TimeBudget과 재현 평가의 StepBudget을 분리한다. 시간이 더 걸리면 많이 탐색되는 효과를 알고리즘 우위로 표현하지 않는다.

단일 배치에 서로 다른 실제 경로가 생길 수 있어 후보 ID는 경로도 구분해야 한다. 품질 탐색은 경로 fingerprint를 ID에 추가한다. 큰 그래프에서 윤곽 상태 수가 400만을 넘는 탐색은 앱에서 건너뛴다.

동기 워커는 탐색 중 cancel 메시지를 즉시 처리하지 못한다. `reqId`로 오래된 결과를 무시하는 것과 실제 계산 중단은 다르다. 즉시 중단은 worker 종료·재생성, 캐시 유지 취소는 chunk/yield 설계가 필요하다. 이를 이미 구현했다고 가정하지 않는다.

## 8. 사람 평가·인식 비교 실험을 이어가는 방법

`docs/recognition-lab.md`를 먼저 읽는다. 동일 candidate ID·자료 fingerprint를 고정하고 렌더러·모델·사전·회전 중 한 축씩 비교한다. 좋은 후보가 전체 풀에 있는데 선택 못하는지, 풀에 좋은 후보가 없는지를 분리한다.

- 이름·점수·방법을 숨긴 자유 명명을 먼저 잠근 뒤 제시 이름의 납득도를 묻는다.
- ‘아무것도 없음’을 허용하고 false positive를 별도 측정한다.
- 기본 사람 다수결은 3명 이상이다. 한 명 smoke 테스트, VLM 판정, 모델 pseudo-label을 인간 품질 검증으로 바꾸지 않는다.
- 같은 경로·회전본·겹치는 인근 영역은 같은 데이터 분할에 둔다.
- 모델별 top-k만 보면 앞단 모델이 좋은 후보를 모두 제거한 사실을 놓칠 수 있다. 모델 무관 표본을 포함하고 전체 oracle 주장에는 고정 풀 전수 판정이 필요하다.
- 이름 사전·프롬프트·renderer가 달라지면 새 방법 ID를 쓴다. 사람 판정 배포 후 비교 방법 추가는 study fingerprint를 바꾼다.
- `rankingScore`와 `rawScore`를 구분하고 서로 다른 모델 원점수를 직접 합치지 않는다.
- 성공 캐시·호출 원장·실제 사용량·에러를 보존한다. API 실패는 인식 실패/none 정답으로 넣지 않는다.
- 대전·대구·송파는 이미 한 번 검증 결과를 본 자료다. 이에 맞춰 다시 튜닝하면 새 독립 검증 자료를 추가해야 한다.

꾸밈선·토스트 설명·제안 이름을 자유 인식 평가 입력에 넣으면 암시 효과가 생긴다. 꾸밈선은 실제 경로/길이/저장 좌표/GPX와 독립인 SVG 표시여야 한다.

## 9. 재현에 필요한 자료와 실행 명령

Git의 코드·보고서만으로 과거 모든 실험을 재실행할 수는 없다. 다음은 `.gitignore`로 제외되어 있다.

- `data/roads/manifest.json`과 manifest가 가리키는 SQLite. 앱 도로 조회에 필요. 원본 PBF는 앱 실행에는 불필요.
- `eval/recognition/model-cache/`: CLIP 모델·processor 캐시. CLIP 해석에 필요.
- `eval/recognition/model-env/`: 현재 Windows Python 환경. 다른 환경에서는 의존성을 다시 설치하고 `CLIP_PYTHON`, `CLIP_MODEL_CACHE`를 지정한다.

## 12. 후속 실험의 노하우와 현재 작업 상태 — 2026-10-13

최신 표현 진단: `exactRoadPortGraph.ts`는 원래 영역 안 그래프의 degree2 구간을 압축하면서 굽은 구간의 전체 실제 노드를 보존한다. 원래 자동12경로 모두 압축→복원에서 순서와 실제 길이가 일치했고, 영역 안 간선 coverage는100%였다. 경로의 압축 연결 구간은35–94개였다. 따라서 압축 arc 깊이32 제한은 모든 기존12경로를 제외한다. 후속 macrocycle 탐색은 arc 깊이128과 총 확장4,194,304 상한을 별도로 기록하고, 방향 전환 수는 다양성 분류에 사용한다. 이 상한은 기존 결과를 보고 선택한 탐색 예산이며 완전 탐색이나 좋은 후보 보존을 보장하지 않는다. 표현 보존은 품질 개선이 아니다. 근거: `eval/recognition/route-improvement/exact-road-port-graph-20261013/results.json`, 설계: `reports/route-improvement-20261012/macrocycle-design-20261013.md`.

### 확인된 최신 개선

2026-10-14 후속: 연속 선분 대응의 sparse/dense 네모100점 계약은 통과했지만 실제 광안리4조건에서는 두 arm 모두 완성0/Q0, 평균72.75 유지였다(169.06초 실행). 바로 직전 압축 간선의 역방향만 제외한 별도 대조도 완성0/Q0였다(174.88초). 정상 self-loop와 나중의 연결길 재사용은 계약에서 보존했다. 역방향 제외는 실제로네모75,704/하트52,237/별67,681/고양이69,359 전이를 거절했으나 충분하지 않았다. 두 방식 모두 각 arm에서 조건당400,000 전이 예산을 사용했으며 DP·적분·최단거리 사전 계산은 이 숫자 밖의 작업이다. 새 결과는 각각 `shape-guided-rollout-continuous-20261013/gwangalli/`, `shape-guided-rollout-no-backtrack-20261014/gwangalli/` 아래에 있다. 원래12조건 평균77.416667은 새로 개선되지 않았다.

다음 구조 대조는 비용만으로 짧은 중간 경로를 먼저 꺼내는 대신, 남은 윤곽 기준점을 지나 실제 시작점으로 닫히는 거리의 하한을 heap 순위에 더하는 방식이다. `orderedClosureBound.ts` 보조 함수와 계약을 작성했다. 이 값은 완성 suffix의 비음수 proxy 비용 하한이며 최종 Q나 중간 prefix 최적성의 증명이 아니다. label 보존·지배 판정에는 기존 cost를 유지해야 한다. 단순한 반경·Q 가중치·총예산 확대는 이 대조에 섞지 않는다.

최신 자동12경로를 고정한 연속 checkpoint 대응 진단도 모두 통과했다. 각 경로의 원래 노드·간선·균일 배치·반경0.16을 유지하고 canonical 시작점에서 원본 꼭짓점+32균일 표본을 실제 선분 내부의 허용 구간에 순서대로 대응시켰다. 시작·끝 대응은 실제 경로 끝점에 고정했다. 이 진단은 checkpoint 순서 가능성만 확인하며, 모든 중간 곡선 위치의 Fréchet 거리·탐색의 완전성·새 품질 개선을 증명하지 않는다. 새 탐색이 이12경로를 생성했다는 뜻도 아니다. 근거: `eval/recognition/route-improvement/continuous-checkpoint-feasibility-20261013/results.json`(원자료/코드 byte hash 고정, 테스트·ESLint 통과).

실제 광안리 고양이의 자동 배치에서도 greedy phase 전진 직후 실제 간선을 거절한 국소 사례51개를 관찰했다. 이51개는 전진 전 단계에서는 거리 조건을 통과했다. 자동 배치400,000 확장에서 다중 단계 전진13,546회, 최대 한 번에7단계였다. 그러나 알려진 자동71점 배치2unit 진단에서는 같은 국소 사례0개, 완성0이었다. 따라서 greedy 전진 문제는 실제로 존재하지만 모든 실패의 단독 원인으로 설명할 수 없다. 원본·관찰 복제본의 반환 결과가 완전히 일치했고 알고리즘을 변경하지 않았다. 자료: `eval/recognition/route-improvement/rollout-greedy-phase-diagnosis-20261013/gwangalli-cat/`의 두 모드. 다음 실제 도로 선분 대응 수정은 노드 간격 계약을 복구한 뒤 별도 품질 대조로 평가한다.

새 rollout의 선분 처리 결함을 재현했다. 동일한 완벽한3.2km 네모를 한 변800m 간선 하나로 표현한 그래프와100m 간선8개로 표현한 그래프는 원래 점수식에서 모두100점·반복0이었다. 그러나 Scheduled 탐색은 드문4노드 표현에서 strict0/Q0, 촘촘한32노드 표현에서 strict8/Q8을 만들었다. 두 경우 실제 확장은2회라 예산 부족으로 이 차이를 설명할 수 없다. guide 전진을 실제 노드 끝점에서만 판단하고 짧은 현재 guide 선분과의 거리로 긴 실제 간선을 먼저 거절하는 구현은 노드 간격에 의존한다.

이는 합성 계약 진단이며 원래12조건의 개선 점수가 아니다. 근거: `eval/recognition/route-improvement/rollout-node-spacing-20261013/results.json`, `tests/eval/rollout-node-spacing-diagnosis-20261013.test.ts`(Vitest·ESLint 통과, frozen module 해시 유지). 다음 수정에서는 실제 도로 선분을 따라 진행 단계 대응을 검색하되 원래 route node를 삽입·변형하지 않고, 원식과 모든 제약을 유지해야 한다. 노드 간격 의존성 복구와 실제 품질 향상을 별도로 검증한다.

남은 unit 예산을 호출에 사용할 수 있게 한 별도 Scheduled 구현도 광안리4그림 비교를 완료했다. 각 arm에서 조건당400,000 확장을 모두 사용(4조건 합1,600,000)했지만 완성0/Q0, 평균72.75 유지였다. 작은 하위 cap을 제거해도 첫 실패가 해결되지 않았으므로 그것을 유일한 원인으로 설명하면 안 된다. 실제 계산량은 첫 fixed-subcap 실험의 합184,470보다 크게 늘었다. ‘동일 최대 예산’은 동일 실제 비용이라는 뜻이 아니다. 테스트 exit0, 타입·정적 검사 및 source 고정 확인.

Scheduled는 먼저 실행한 prefix 또는 suffix가 unit 예산을 모두 쓸 수 있다. 기록된 suffix128회/조건 중 실제 양수 예산을 받은 호출은 네모16/하트14/별14/고양이10개였고 나머지는 예산0이었다. 예산0 호출을 독립적인 충분한 탐색 실패로 세지 않는다. Q 선택 뒤 확장은0이라 feedback 품질 효과는 여전히 검증되지 않았다. 출력은 `eval/recognition/route-improvement/shape-guided-rollout-scheduled-20261013/gwangalli/results.json`이다. 다음 진단은 mandatory greedy phase 전진이 이전 단계에서 가능한 실제 간선을 배제하는지 확인하며, 반경·점수식·총예산을 다시 늘리는 접근은 보류한다.

rollout 실패 관찰에서 광안리 고양이의 prefix18회는 전부1,875 확장 한도, suffix4회는 전부546 한도에 도달했다. heap이 빈 실패는0회이고 suffix의 마지막 윤곽 단계 도달도0회였다. 원본과 관찰 복제본의 반환값은 일치했다. 이는 작은 하위 예산이 살아 있는 탐색을 중단했다는 증거이며, 큰 예산이면 좋은 경로를 찾는다는 증명은 아니다. `rollout-suffix-diagnosis-20261013/gwangalli-cat/results.json`에 근거가 있다.

### 다음 실험을 선택할 판단 기준

먼저 새 cascade가 저장 최고를 읽지 않는 자동 실행에서 기존 결과를 보존하고 개선하는지 확인한다. 개선되면 원래12조건 전체를 실행하고 비용·실패·정밀 점수를 보고한다. population 후속안으로는 같은 자동 후보 풀의 좋은 실제 고리를 면 집합으로 엄격히 재구성해 부모로 쓰고, 별도 다양성 슬롯에 낮은 점수의 중간 상태를 유지하는 방안을 논의했다. 아직 구현·효과가 확정된 방안은 아니다.

### 최신 후보 생성 대조에서 배운 점

최신 자동12경로는 모두 featureCoverage1/spikes0이었다. 원식의 남은 병목은 정규화된 양방향 윤곽 편차와 RDP 급회전이다. 실제 raw node의 turn 비용과 RDP 급회전은 같은 지표가 아니다. 더 짧은 대체 구간은 윤곽 coverage를 잃고, 더 길게 따라가는 구간은 추가 꺾임을 만들 수 있다.

`multiSegmentRepair.ts`는 같은 대안을 최대2/최대6 구간으로 조합했지만 두 조건의 기존 자동 경로를 넘지 못했다. `localArcSegmentRepair.ts`의 단조 윤곽 안내도 이득이 없었다. 모두 라우팅 성공했으므로 실패를 단순 timeout으로 돌리지 않는다. 넓은 phase 거리 허용과 같은 실제 노드에서의 여러 phase 전진은 윤곽 밀착을 보장하지 않는다.

`normalizedArcRepair.ts`의 길이·편차 비용 정규화 첫 대조도 이득이 없었으나, 다양성 벌점까지 작은 길이 epsilon에 곱해져 고유 대안 수가57/46→22/19로 줄어드는 혼입이 있었다. 이를 정규화 자체의 실패로 일반화하지 않는다. 비용 항을 바꾸면 단위·diversity의 상대 세기·실제 고유 후보 수·실제 Q평가 횟수를 함께 확인한다. epsilon이나 phase 수를 결과에 맞춰 계속 바꾸는 대신 별도 원인 대조를 사전 고정한다.

최신 자동 결과 뒤 기존 anneal을 붙인12조건 평가도 표시평균77.4167 유지, 광안리 하트의 정밀점수만 소폭 개선했다. 원식·실제 경로 검증과10개 source byte 스냅샷을 남겼다. 저장된 자동 결과에서 후속 단계를 평가한 것이므로 도로부터 새 전체 파이프라인을 재실행했다고 표현하지 않는다.

각 결과·한계는 `reports/route-improvement-20261012/progress.md`와 `anneal-cascade-20261013/`, `multi-segment-20261013/trial-v1/`, `local-arc-segment-20261013/trial-v1/`, `normalized-arc-segment-20261013/trial-v1/`에 있다(뒤 네 경로는 `eval/recognition/route-improvement/` 아래). 독립 holdout-v2는 계속 보존 중이다.

### 마지막 인계 시점의 추가 결론

최신 자동 결과에 population v2를 붙인 12조건 대조도 평균77.4167, 정밀77.317593으로 유지됐다. 실행 근거는 `eval/recognition/route-improvement/population-cascade-20261013/`에 있다. 낮은 점수의 중간 상태를 보존하는 기능과 실제 최종 품질 개선을 구분해야 한다.
