# v13 방향 통제 진단과 다음 생성 구현

**같은17개 추천 경로의 표시 방향만 고정하자3AI 명확 다수결은4/75→7/75로3조건 회복했다. 기존 첫 후보8/75에는 못 미치며 최종 목표는 미완료다. 사람 인식은 미측정이다.**

원본1003개 도로·선택ID·점수·75슬롯·58보류는 완전히 동일하다.17 GPX도 바이트가 같다.5개 추천의 각도만 바뀌었으며 이전3개 연구와 본문 픽셀을 대조해14개는 평가자별 기존 판정을 연결했다. 신규 고유 그림3개만 같은3AI에게 방법·참고·이름을 숨겨 자유 명명을 받았다. 과거 동일 픽셀 판정 충돌은0이다. 평가자별 명확은0/7/9이며 AI끼리 상관될 수 있다.

진단 사전 기준인+2조건 이상은 통과했다. 이것은 표시 정책의 개발상 개선이며 생성·분류 개선이나 v12 기준 통과가 아니다. 원래 >=13/75 및 동물3종·사물3종 각각2지역 기준은 여전히 실패다. 현재 동물 추천은3조건뿐이라 방향을 고쳐도 다양성 기준은 충족할 수 없다. 사후 여러 방향 중 좋은 판정을 고른 것이 아니라17개 모두의 방향을 미리 고정했다.

## 다음 생성 구현의 현재 상태

새 core는 실제 CSR 도로만 탐색하고, 두 특징 팔·특징 간의 무방향 간선/노드 공유를 차단한다. 특징 경계를 먼저 예약한 뒤 나머지 외곽을 완성한다. 몸통 연결이 특징 내부에 접속하지 못하도록 원래 경계의 entry/exit만 접합점으로 허용한다. 고정 영역·개별/누적 확장수·마감시간을 지키며 연결 실패를 직선으로 채우지 않는다. 몸통끼리의 재사용은 기존처럼 허용하고 완성 뒤 거리/반복 감사를 별도로 요구한다.

- `src/lib/route/distinctiveFeatures.ts`:25종 전체 정의,18종 지원·7종 명시적 미지원. 특징 폭·깊이·방향·상대 간격을 고정된 원본 배치 좌표계에서 검사한다. 실제 사람의 해부학 인식 정답이 아닌 구조 가설이다.
- `src/lib/route/boundaryRouting.ts`:영역·공유 노드/간선·예산 제약을 지키는 실제 도로 구간 탐색.
- `src/lib/route/boundaryCompletion.ts`:같은 배치/anchor의 일반 완성과 독립 특징 경계 완성. 완성만으로 유효 도로 또는 사물 인식을 인증하지 않는다.
- `eval/recognition/road-ranker-20261102/boundary-bank-v14.json`:같은25종×3지역75조건,기존 생성 배치에서 준비한4398개 배치. A/B가 같은 목록을 사용하도록 동결했다. 신규 도로 검색은 아직 실행하지 않았다.

미지원7종은 fish,whale,house,apple,mug,pants,hammer다. 원래 외곽의 한 특징을 둘로 억지 분할하거나 단순 모서리를 독립 특징으로 부르지 않는다. 이 정의만으로25종 전체를 해결했다고 할 수 없다. 미지원 종류의 기존 추천을 유지하는 fallback 여부도 다음 실행 전 프로토콜에서 명시해야 하며, 그것을 특징 개선으로 세면 안 된다.

## 확인과 남은 일

새 TypeScript core21검사·타입 검사·lint를 확인했고, 준비 목록 생성1검사가 통과했다. 실제 간선·3~8km·반복<=.2를 만족하는 합성 도로 fixture에서도 완성을 검사했지만, 새로운 실제3지역 생성 성과는 아직 없다. 기존 원본12조건·점수식·holdout-v2·앱 기본은 보존했다.

다음은 남은 통합 검토를 반영하고 A/B 실행 예산·fallback·성공/실패 기준을 고정한 뒤75조건 생성과 익명 검토를 수행하는 것이다. 가설과 과거 실패 근거는 v13-generation-expert-plan.md,방향 프로토콜은 protocol-v13-orientation.md,원본 판정은 ai-review-v13-*.json,집계는 diversity-v13-canonical-ai-results.json에 보존했다.
