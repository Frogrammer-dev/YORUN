## 해석

H와 I는 사람이 확인한 개발 도로를 target 조건부 점수로 자동 선택했지만, 이 사례는 새 독립 test가 아니며 I만의 효과도 아니다. 전체에서는 얻은 사례와 잃은 사례가 상쇄됐다. 따라서 'global class argmax를 없애면 전체 목표가 개선된다'거나 '템플릿 IMAGE가 손그림 query보다 낫다'는 결론은 지지되지 않는다. 같은 cosines가 인간 읽힘 확률을 뜻하지 않고, 임의 자연도로에서 target을 발견하는 모델을 검증한 것도 아니다. 사람 baseline 도로의 판정 부재와 기존 실제 사람 한 사례의 제한은 그대로다. 학습/label fit이 없다는 장점과 성능 검증 실패는 별개다. 기존75요청 실패·primary0·엄격 다양성 기준을 보존하며 최종 목표는 미완료다.

## 다음 권고: 새 지역에서 동결 비교만

동일1003풀에서 score·query·회전·거절 규칙을 더 맞추는 작업은 중단하고, 계속 검증하려면 **현재 G/H/I 전체 계약을 동결한 채 새 사전 지정 지역**에서 시험하는 편이 낫다. 25종×3지역75 또는×6지역150 중 분모를 먼저 고정하고, 공원처럼 쉬워 보이는 곳만 고르지 말고 격자 주거·구도심 불규칙망·상업/산업·하천 인접 등 도로 구조와 밀도가 섞이도록 지역 포함 규칙을 모델 출력 전에 명시한다. 이전 개발 지역과 인접 동일 road family는 피하고, 후보 생성·예산·geometry 대표·canonical·학습 checkpoint/query·75개 또는150개 전체 분모와 실패 처리를 고정한다. 같은 세 방법의 대응 요청 비교이며 기존75 실패를 새 결과로 대체하지 않는다. 이 연구를 범용화하려면 현재 fixed1003/75 입력 검사와 실제 재사용 가능한 검색 core를 구별해야 하지만, 여기서는 코드 수정이나 실행을 제안 이외로 수행하지 않는다. 앱 기본 변경 전에는 방법/target/참고를 숨긴 **새 사람의 paired 요청 검토 표본**을 지역·동물/사물 층화 hash로 점수와 무관하게 동결하고, 방법별 그림을 나란히 노출해 정답을 암시하지 않는 제시 순서를 사용한다. 동일 pixel은 중복 증거로 세지 않고 개별 자유 명명·clear·target 일치·보류를 분리한다. 한 개발 positive를 사람 test에 다시 넣거나 성공 사례만 선별하지 않는다. 새 지역 시험도 실패할 수 있으며, 사람 검증과 고정 기준을 통과하기 전에는 사용 가능한 코드가 있다는 사실을 제품 효과 입증으로 바꾸지 않는다.
