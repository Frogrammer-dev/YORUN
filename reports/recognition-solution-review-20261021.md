# 부분 배치가 사물로 읽히지 않는 문제: 협업 검토와 다음 설계

2026-10-21. AI 전문가·후보 풀 조사·의미 근거 검토·방법 비공개 원본 평가를 나눠 진행했다. 결론은 **홈의 복잡도에 가중치를 더하는 방식은 중단하고, 객체 가설을 바탕으로 실제 경로 생성과 반증 검사를 연결해야 한다**는 것이다. 단순한 템플릿 재순위도 이번 비교에서는 충분하지 않았다. 아래 해결 설계는 성능 보장이 아니며 일부만 실험 구현했다.

## 이번에 추가로 확인한 근거

### 1. 선택된 15개 밖의 후보도 조사

대전·대구·송파의 같은 6,924개 유효 후보를 복원해, 모델 무관 해시 표본 12개·단순 윤곽 대리 지표 상위 9개·parts 상위 9개, 총 30개를 별도 조사했다. 명확한 사물 0/30, 약한 연상 6/30이었다. 이전 15개와 중복 3개를 제외하면 새 27개에서 명확한 사물 0/27, 약한 연상 5/27이다. 이는 전체 풀의 부재 증명이 아니며, 같은 모델 계열 AI의 탐색 판정이다. 단순 윤곽층은 parts salience가 낮은 순이라는 대리 정의이므로 잘 그린 모든 단순 윤곽을 대표하지 않는다.

근거: `tests/eval/pool-audit-20261021.test.ts`, Git 제외 `eval/recognition/pool-audit-20261021/README.md`, 원본 30개·판정·해시.

### 2. 같은 풀에서 전체 객체 가설과 최악 구간을 검사

`routeHypotheses.ts`를 구현했다. 원본 SHAPES를 바꾸지 않고 실제 자연 고리를 48점의 순서가 있는 윤곽으로 비교한다. 이동·회전·균일 확대만 적용하며, 전체 잔차로 계열별 상위 3가설을 추린 뒤 평균 편차와 가장 어긋난 연속 1/8 구간의 편차를 함께 본다. 실제 경로는 수정하지 않는다. 동물·사물·기본도형을 같은 원점수 경쟁으로 섞지 않고 basic→animal→object 슬롯으로 각각 하나씩 고른다.

현재 실험은 **고정 원본 가설 은행의 근사 검색**이다. 의미를 학습한 모델, 해부학적 부분 검출, 가설 밖 대상의 발견, 나쁜 가설의 의미적 거절을 구현한 것이 아니다. 계열별 슬롯과 공간 중복 제거 순서가 결과에 영향을 주며 composite 점수의 전역 최적도 아니다. 기존 해시 첫 후보를 보존하던 parts와 달리 첫 슬롯도 실제 단순 윤곽 적합도로 교체했다. API에 가설 이름·점수·템플릿은 보내지 않는다.

같은 도로·seed·거리·반복·영역 제약으로 baseline과 hypothesis가 각 지역 3개씩 선택했다. 합집합 18개를 별도 AI 평가자에게 방법·예상 이름 없이 원본 PNG만 제시했다.

| 이번 동일 평가자·동일 기준의 비교 | baseline | hypothesis |
|---|---:|---:|
| 선택 수 | 9 | 9 |
| 명확한 기본도형 | 2 | 2 |
| 명확한 사물·동물 | 0 | 0 |
| 약한 연상 | 3 | 4 |
| 없음 | 4 | 3 |
| 주관 AI 점수 평균 | 39.22 | 40.11 |

이 평가자는 기본도형 인식을 명시적으로 구분했다. 이전 보고서의 22.22/28.89와 판정자·기준이 달라 직접 성능 상승으로 비교하면 안 된다. 새 비교 안에서만 39.22 대 40.11을 읽는다. 동일 모델 계열의 별도 호출이며 사람의 독립 인식률이 아니다. 명확한 사물·동물의 개선은 없으므로 앱 기본은 baseline을 유지한다.

자료: `eval/recognition/hypothesis-pilot-20261021/{results.json,judge-raw.json,summary.json}`. PNG와 소스 해시, 판정 분모·누락·중복을 집계 시 검증했다. 6,924개 전부에 대한 의미 판정이 아니다. 원래 12조건 점수식·자료·holdout-v2·거리 제한은 변경하지 않았다. 외부 API 호출은 0이며 앱 외부 모델 비용을 측정한 실험도 아니다. 가설 검색의 추가 CPU 연산은 있으므로 동일 실행 시간 비교라고 부르지 않는다.

### 3. 현재 AI 관찰 근거도 관계 인증은 아님

별도 검토에서 사각형 전체 구간 하나에 머리·몸통·꼬리를 중복 귀속한 응답이 현재 형식 검사를 통과함을 재현했다. 파서의 계약은 형식·출처 확인이므로 이것 자체가 버그는 아니다. `semantic:unverified`는 유지한다. 단순히 observedParts 항목 수를 늘리거나 confidence를 요구해도 관계 일관성을 증명하지 못한다. [구체적 반례와 자문](semantic-evidence-review-20261021.md).

## 권장 해결 방향

### 우선 1: 실제 부분 관계를 목표로 후보를 생성·수선

현재처럼 완성된 면 합집합 외곽을 대량 수집한 뒤 이름을 붙이는 단계만 개선하면, 목·다리·꼬리처럼 해석할 부위의 위치와 비율을 동시에 바꾸기 어렵다. 다음 실험은 도로에서 얻은 큰 덩어리·돌출·연결부를 바탕으로 2–3개 가설을 세우고, 가설을 만족하도록 **실제 도로 간선의 일부 구간을 다시 찾는 방식**을 우선한다.

예를 들어 기린 가설이라면 ‘몸통과 별개의 작은 머리, 그 사이의 긴 목, 목이 몸통 위쪽에 붙는 순서’를 하나의 배치 안에서 요구한다. 긴 돌출 하나를 목·다리·꼬리 어느 것으로든 해석하는 후보는 낮춘다. 눈·무늬가 없어도 되는 외곽 가설과 내부 획이 핵심인 가설은 구분한다. 단순 윤곽으로 표현되는 하트·국가·바나나 등에 여러 부위를 강제하지 않는다.

구현할 실험 상태는 도로상의 현재 간선 경로와 가설의 부분 대응을 함께 가진다. 점수는 전체 편차, 최악 연속 구간, 순서와 연결 위치, 부위 간 크기 비율, 가설로 설명되지 않는 긴 여분 구간을 구분해 기록한다. 원본 도형을 비선형으로 늘여서 점수를 높이지 않는다. 여러 국소 구간의 후보를 만들되 실제 도로 연결·폐곡선·정확한 3–8km·반복 0.2 이하·원래 영역을 통과해야만 채택한다. 기존 단순 윤곽 후보는 별도 보존한다.

새 내부선·가지 생성은 무조건 켜지 않는다. 지금은 가지가 있는 후보도 서버 실험에서 제외되며 기존 branch/group 코드는 이미 존재한다. 이를 활용할 때는 **실제 화면에 보이는 간선 합집합**과 **실제로 달리는 순서**를 분리해 검증하고, 연결선·왕복도 거리·반복·보이는 선에 포함해야 한다. 기존 폐윤곽 동일 풀 비교와 내부선/가지 후보군 확장은 다른 실험으로 보고한다.

### 우선 2: AI는 가설과 반증을 맡고, 좌표 생성은 도로 코드에 남김

사용자가 선택한 주변 도로 기반의 유동적인 이름·참고 그림 방향은 유지한다. 다만 LLM이 설명 그림을 잘 만들었다는 사실을 원본 경로가 알아보기 쉽다는 증거로 쓰지 않는다. 가설은 관찰된 선의 구간·상대 관계·반증과 함께 제안하고, 원본만 보는 명명 단계와 꾸밈선 생성 단계를 분리한다. 없는 눈을 그려야만 성립하는 토스트·동물은 원본 인식 성공에서 제외한다.

첫 도입은 추가 비평 모델이나 회전별 여러 호출보다, 현재 후보당 한 호출 안에서 가설 종류(단순 윤곽/부분 배치), 관찰 구간, 실제 관계, 어긋나는 특징, 필수로 상상해야 하는 특징을 구조화하는 것이다. 출력이 길어져도 기존 최대 3후보·동일 모델·총 이미지/토큰 상한으로 비교하고 실제 사용량을 따로 기록해야 한다. 이번 작업에서 서버 프롬프트·스키마를 바꾸거나 API 품질을 실측하지는 않았다.

### 우선 3: 작은 실험의 통과 조건부터 고정

다음 후보 생성 실험은 이미 확인한 세 개발 지역을 튜닝 자료로 명시하고, 기존·새 생성기의 탐색 시간/단계·총 평가 후보·외부 호출 예산을 맞춘다. 현재와 같은 원본 자유 명명 기준을 고정한 뒤, 유효성 실패는 실패로 남긴다. 단순 도형 성과와 사물·동물 성과를 분리하고 `none`을 정상 결과로 인정한다. 어려운 조건을 제거하지 않는다.

양성 대조군에는 사람이 이미 그린 단순 윤곽·부분 구조 작품을, 음성에는 부분의 위치를 섞은 모양·필수 부위를 심하게 어긋나게 한 모양·여분의 긴 돌출을 넣는다. 실제 작품 이미지를 참고용으로 검토하는 것과 그대로 학습 데이터로 사용하는 것은 구분하며, 현재 자료만으로 새 학습 모델의 우위를 주장하지 않는다. 이 개발 평가에서 동물·사물의 자유 인식 개선이 나타난 뒤에만 새 독립 지역과 사람 평가로 확장한다. 사후 임계값 조정으로 80% 달성을 만들지 않는다.

## 관련 연구에서 가져올 점과 적용 한계

- [SketchGNN 원 논문](https://arxiv.org/abs/2003.00678)은 점·획·전체 스케치의 구조를 그래프로 다루는 의미 분할 연구다. 부분과 전체를 함께 표현하는 설계 참고이며, GPS 외곽선에 그대로 적용해 같은 성능을 얻는다는 근거가 아니다. 이번에 가중치를 설치하거나 학습하지 않았다.
- [GPS art 자동 경로 계획 원 논문](https://www.sciopen.com/article/10.1007/s41095-019-0146-z)은 GPS 작품의 자동 경로 생성 문제를 다룬다. 현재 발견형 이름 붙이기의 해결이나 사람 인식 80%를 보장하지 않는다. 후보 생성과 인식 문제를 나눠 설계해야 한다는 맥락에서 참조했다.

이번 실험에 대한 우선순위와 통과 조건은 코드·추가 관찰에서 도출한 프로젝트별 제안이다. 위 연구의 성능 수치를 프로젝트 예상치로 이전하지 않았다.

## 현재 구현과 재현

새 파일: `src/lib/art/routeHypotheses.ts`, `tests/route-hypotheses.test.ts`, `tests/eval/hypothesis-pilot-20261021.test.ts`, `scripts/recognition-lab/hypothesis-pilot-summary.mjs`. 선택기는 네 번째 인자 `hypothesis`일 때만 활성화된다. 제품 기본·서버 모델·API 스키마·원본 경로·원래 fit/shapes는 바꾸지 않았다.

PowerShell에서 `$env:ROUTE_HYPOTHESIS_PILOT='1'` 후 `npx vitest run tests/eval/hypothesis-pilot-20261021.test.ts`, 저장된 원본 판정 집계는 `node scripts/recognition-lab/hypothesis-pilot-summary.mjs`로 재현한다. 판정 자체는 별도 AI의 시각 결과이므로 집계 스크립트 재실행이 새 의미 평가를 수행하지는 않는다.

위 우선 1의 부분 관계를 보존하는 경로 수선과 우선 2의 관계/반증 서버 출력은 **아직 미구현**이다. 이번에는 실패 원인을 분리하고, 단순 재순위만으로 부족하다는 근거와 다음 구현의 구체적인 경계를 확보했다.
